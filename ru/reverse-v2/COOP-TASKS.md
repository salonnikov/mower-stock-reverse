# COOP-TASKS — доска обмена между аналитиком и прошивальщиком

Назначение: асинхронный обмен заданиями и результатами между двумя людьми.
- **Аналитик** (реверс/анализ, НЕ прошивает): ставит задания в разделе «ОТКРЫТЫЕ ЗАДАНИЯ», даёт точные адреса/контекст.
- **Прошивальщик** (правит и заливает прошивку, работает с железом): выполняет, пишет ответ в «РЕЗУЛЬТАТЫ / ОТВЕТЫ», при необходимости заводит встречные вопросы.

## Правила
1. Каждое задание = блок `### TASK-NNN` со статусом: `OPEN` → `IN PROGRESS` → `DONE` / `BLOCKED`.
2. Задание самодостаточно: адреса, файлы, что снять, критерий готовности — без ссылок на «наш прошлый разговор».
3. Ответ пишется под тем же номером в «РЕЗУЛЬТАТЫ / ОТВЕТЫ» с датой.
4. Прошивальщик НИЧЕГО не заливает, пока задание явно не просит залить; по умолчанию задачи read-only (SWD-чтение).
5. Дату ставить абсолютную (YYYY-MM-DD).

## ОТКРЫТЫЕ ЗАДАНИЯ  (аналитик → прошивальщик)

### TASK-001 — снять сырое окно ADC катушек с ЗАВОДСКОЙ прошивки chip2  · статус: OPEN
**Зачем:** заменяем родные катушки границы на две неродные (одинаковые). Чтобы пересчитать
порог детекции, нужна реальная амплитуда сигнала новых катушек в отсчётах ADC.

**Условия стенда:** заводская прошивка на chip2 (перепрошивать НЕ надо), провод периметра
под током/сигналом, катушки поднесены к проводу. lift = none.

**Подключение:** SWD к **chip2** (не chip1). Отсчёты катушек в chip1 не попадают — только в chip2.

**Что прочитать по SWD (RAM chip2, halt → read → resume):**
- `0x20000094` — base voltage (16 бит), автокалиброванный нуль катушки.
- Дескриптор сенсора: найти объект board_sensor (в декомпиле `*(int*)(DAT+4)`), поля:
  - `+0x92` — длина окна (ожидаем 800 или 235),
  - `+0x48` — указатель на буфер сэмплов #1 (short[len]),
  - `+0x68` — буфер #2 (short[len]),
  - `+0x70` — буфер #3 (int[len]).
- Снять **само окно**: дамп буфера `+0x48` на `len` × 2 байта, минимум 3–5 повторов
  (с проводом под током и без — для контраста).

**Критерий готовности:** приложить к TASK-001 в ответах: значение base voltage и
дамп(ы) окна (bin или CSV отсчётов) для новых катушек. По ним аналитик посчитает новый
порог (сейчас захардкожен ±2500 в `FUN_0801baf8`).

**Референс для поиска адресов:** [reverse-v2/chip2/decompiled_all.c](chip2/decompiled_all.c)
— `FUN_08012b6c` (калибровка базы, стр. 6349), `FUN_08019e34/eb8` (окно 800/235),
`FUN_0801baf8` (порог ±2500). Разбор целиком — в разделе анализа chip2.

**Открытый вопрос к прошивальщику:** L и R катушки — это два раздельных ADC-канала или
мультиплекс одного? Нужно для того, как физически сядут две новые катушки. Если видно по
дескриптору/схеме — отметь в ответе.

### TASK-002 — второй постоянный SWD-жгут для chip2 (свои пины, без перекидывания)  · статус: OPEN
**Зачем:** убрать «слабое место» — физическое перекидывание проводов между chip1 и chip2.
Делаем два постоянных жгута; выбор чипа = запуск нужного конфига OpenOCD.

**Существующее (chip1, НЕ трогать):** `bcm2835gpio_swd_nums 25 24`
(сверено с фото разводки [dist/wiring-rpi1-gpio-swd-v2.png](../dist/wiring-rpi1-gpio-swd-v2.png)
и [dist/wiring-rpi2-gpio-swd-v1.png](../dist/wiring-rpi2-gpio-swd-v1.png))
- SWCLK = GPIO25 = физ. пин 22
- SWDIO = GPIO24 = физ. пин 18
- GND   = физ. **пин 6**  ← земля chip1 именно на пине 6, НЕ 20

**Добавить (chip2), соседний ряд той же правой колонки:**
- SWCLK2 = GPIO8 = физ. пин 24
- SWDIO2 = GPIO7 = физ. пин 26
- GND2   = физ. пин 25

GPIO7/8 свободны (SPI0 не используется, SWD = bit-bang bcm2835gpio). Уровни 3.3 В у GD32 и Pi
совпадают → без level-shifter. 3 провода на chip2: CLK+DIO+GND. Землю держать рядом с сигналами.

**Правка конфигов:** сделать копии chip2-конфигов ([tools/rpi-swd/chip2-*.cfg](../../tools/rpi-swd/))
с заменой строки `bcm2835gpio_swd_nums 25 24` → `bcm2835gpio_swd_nums 8 7`. chip1-конфиги
(`gd32-*.cfg` и т.п.) оставить на `25 24`.

**Правила:** провода не перекидывать; поднимать chip1 ИЛИ chip2 по очереди (два инстанса
OpenOCD одновременно не гонять).

**Критерий готовности:** отписать сюда — жгут chip2 распаян на пины 24/25/26, chip2-конфиг на
`8 7` читает IDCODE/DPIDR chip2 (DPIDR ≠ deadbeef). После этого можно делать TASK-001, не трогая
провода chip1.
