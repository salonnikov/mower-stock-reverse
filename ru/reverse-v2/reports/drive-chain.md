> ⚠️ **ПОПРАВКА 2026-07-13 (фото платы):** физически на плате НЕТ Allegro A4963 — привод =
> **три Fortior FU6832N** (8051+FOC, своя прошивка), «A4963-протокол» эмулирует прошивка FU6832.
> Все пометки **✔D** (семантика по даташиту A4963: POR-дефолты, RUN=1, VBB и т.п.) — **аннулированы**.
> Пометки **✔C** (что chip1 шлёт по SPI: кадры, CS, тайминги, регистры) — остаются валидными.

**Легенда строго:** ✔C = доказано кодом дампа · ✔D = семантика по даташиту A4963 · ❓ = НЕ проверено физически (нужен чистый стенд-замер) · ⓗ = вывод/догадка.

## 1. Железо привода
- Колёса + нож = **3× BLDC на Allegro A4963** (sensorless), общий `motor_spi_mutex`. Драйверы `driver_{left,right,blade}_motor_snk_v2.c`, `a4963_snk_v2.c`. ✔C
- A4963 управляется по **SPI** (конфиг/направление/режим) + **аппаратный PWM-пин** (задание скорости). ✔C/✔D

## 2. SPI-кадр A4963 ✔C
`FUN_0808408c` (verify-write) / `FUN_080840d8` (send): слово = `[15:13]=адрес рег(0..7) | [12]=W(ставится |0x1000 при отправке) | [11:0]=данные`. Readback-сверка `(word&0xfff)==readback`, до 0x31 попыток.

## 3. Карта регистров A4963 (по даташиту) ✔D
| addr | рег | ключевые поля |
|---|---|---|
|0|CONFIG0|dead-time, blank-time, recirc|
|1|CONFIG1|VDS-порог, current-limit, invert-PWM, fast-decay|
|2|CONFIG2|PWM-период, overspeed, pos-P|
|3|CONFIG3|hold-time/duty, pos-I|
|4|CONFIG4|start-speed, startup-duty, speed-P|
|5|CONFIG5|phase-adv, **SMX[6:4]=макс-скорость(передача)**, FG-выход, speed-I|
|7|**RUN**|**RUN[0], DIR[1], BRK[2], restart[3], demand DC[8:4], stop-on-fail[9], CM[11:10]=режим**|

## 4. Init левого мотора: 8 слов A4963 ✔C+✔D
Пишутся из shadow `+0x30..+0x3e`; **reg6/MASK не отправляется** (остаётся дефолт). Слово reg7 (RUN) = `0xee0d`:
- **RUN=1** (выходной каскад ВКЛючён), DIR=0 (вперёд), **BRK=1**, restart=1, **demand DC=0**, stop-on-fail=1, **CM=11 (ClosedLoopSpeed)**.
→ **A4963 в RUN уже с init и остаётся** (нет отдельной «включить RUN потом»). Serial-demand держится 0.

## 5. Что реально задаёт скорость — PWM на TIMER2 CH3 ✔C/✔D
- Init канала: `FUN_0807f474(TIMER2,3,…)` → CHxMS=00 (**output mode**)+CHxEN; `FUN_0807f648(…,0x60)` → OCxM=PWM; `FUN_0807f696(TIMER2,3,0)` → CH3CV=0. TIMER2=`0x40000400`, CH3CV=`0x40000440`. ✔C
- `set_left_motor_speed` = **`FUN_0805f620`** (форс-разобрана, 1114 б) и зеркало `set_right` = **`FUN_0806fe66`** (1070 б): «коробка передач» `pwm = speed*0x1c20/gear_max`, gear_max∈{6141,3069,718 в PWM-единицах}, при смене передачи — `FUN_0801f4dc`; финал `FUN_0805f300`(dir)+`FUN_0807f696(TIMER2,3,pwm)`. ✔C
- Serial-demand в RUN (DC[8:4]) остаётся 0 → **скорость идёт через PWM-пин, не по SPI.** ✔C/✔D

## 6. Поправки к прежним ярлыкам ✔C+✔D
- **`FUN_0801f4dc` ≠ «brake to dir».** Пишет CONFIG5 SMX[6:4] = **выбор макс-скорости (передача)**: 1→1533, 2→3069, 3→6141 rpm. Совпадает с лог-константами `6141`/`1533`. Это gear-selector, НЕ направление и НЕ тормоз.
- **Направление** = `FUN_0801f4c6` (бит DIR reg7). set_left_dir=`FUN_0805f300`.
- **«Тормоз» мотора** = НЕ снятие RUN и НЕ бит BRK (BRK всегда 1), а **сброс PWM-demand в 0** → при RUN=1&BRK=1 A4963 даёт электродинамическое торможение/удержание (по даташиту). ✔D
- Выбега (coast, BRK=0) в коде НЕТ.

## 7. Состояние по умолчанию после init ✔D
`RUN=1, BRK=1, CH3 duty=0%` → PWM неактивен → колесо в **торможении/удержании** (не крутится, не на выбеге). **Единственное, что гейтит вращение — ненулевой duty в CH3CV.** ← это МОДЕЛЬ (код+даташит), НЕ живой замер.

## 8. Гейтинг мотор-контура ✔C
- **hs-loop `FUN_08053af0`** — многоскоростной диспетчер колбэков (шаг 10мс): массив `+8` (быстрейший, мотор-контур) каждые 10мс, `+0x30` каждые 20мс, `+0x6d` реже (машина состояний). ✔C
- **Очередь мотор-команд** `pri_data+0xe4` (movebase pri_data, синглтон RAM `*0x20000338`): кольцо 6×0x24, курсор `+0xe4`. Писатели `FUN_0801fb04`(mode2)/`FUN_0801fe8c`(mode1)/`FUN_08020164`(turn). Исполнитель (консюмер) — тело executor-таска (в дыре ⓗ). ✔C(писатели)
- **Border-навигация — НЕ отдельный путь**: реактивный cycle («border out, cycle left») внутри `FUN_08030128` (process_cutting run, state 5) и process_find_bd (state 6), дёргает те же примитивы. → **border-cycle активен ТОЛЬКО в state 5/6.** ✔C
- **`manual set` (0x30000006/07)** пишет байт-флаг (0=manual/0xFF=quit), мотор-контур его НЕ читает → приводом НЕ управляет (глушит авто-старт по расписанию). ✔C
- **Прямая инъекция скорости в прошивке**: `FUN_0803b6f4(L,R)` в state {1,7,8} и heading-контроллер `FUN_0805fdd4` (enable-байт==1) задают скорость колёс, минуя очередь/границу. (Точный vtable-offset метода set-speed из статики неоднозначен — `+0x38` оказался геттером; надёжные писатели CH3CV = set_left `FUN_0805f620`/set_right `FUN_0806fe66`.) ✔C(писатели)/ⓗ(точка vtable)

## 9. Полная цепочка (сквозная, с отмеченной дырой)
```
hs-loop FUN_08053af0 (10мс, колбэки +8)
  └► process_*_run (state-dispatch) ─┐
       state 5/6: FUN_08030128 border-cycle ─┤ пишут очередь +0xe4 через
       прямая: FUN_0803b6f4 (state 1/7/8)   ─┘ примитивы FUN_0801fb04/fe8c/08020164
            └► movebase vtable +0x38 (set L,R)         [консюмер очереди = executor-таск, ⓗ дыра]
                 └► set_left FUN_0805f620 / set_right FUN_0806fe66  (gear-map)
                      ├► FUN_0801f4dc  → A4963 CONFIG5 SMX (передача) по SPI
                      ├► FUN_0805f300→FUN_0801f4c6 → A4963 RUN.DIR по SPI
                      └► FUN_0807f696(TIMER2,3,pwm) → CH3CV duty  ──► A4963 PWM-пин ──► мотор
одометрия (обратная связь): тахо A4963 ──► TIMER3 (0x40000800) input-capture
                             ──► ISR FUN_0805fbc0/FUN_0805fd45 → тики/скорость
```

## 10. ❓ ЧЕГО НЕ ЗНАЕМ (нужен чистый стенд-замер)
- Крутит ли **физически** ненулевой CH3CV колесо; тормозит ли CH3CV=0. Это модель код+даташит, НЕ измерение. Прежнее «CCR=0 остановил» = false-positive (упор в border-провод).
- Точная роль PWM-пина A4963 в режиме ClosedLoopSpeed (демаунд vs энейбл) — ⓗ.
- Масштаб CH3CV→rpm; тело executor-таска (консюмер очереди).

## 11. Протокол чистого стенд-теста (когда будет железо)
1. Колёса вывешены, нож физически отключён.
2. Косилку — в **не-режущее** состояние (НЕ 5/6): напр. state 1/7/8 (тогда `FUN_0803b6f4` пишет `+0x38` напрямую) или наблюдать в state 4 (departure, прямая езда). manual-set не обязателен.
3. По SWD независимо варьировать: (a) только CH3CV TIMER2 (0x40000440) при известном A4963-состоянии; (b) A4963 RUN.DIR/CONFIG5 по SPI. Смотреть тики одометрии (TIMER3 capture) + физическое вращение.
4. Так вычленить, что именно вращает: только PWM-duty, или нужно ещё что-то по SPI.
