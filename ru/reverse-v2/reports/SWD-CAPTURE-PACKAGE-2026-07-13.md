# Оффлайн-пакет для ОДНОГО SWD-захода к заводской прошивке (2026-07-13)

Цель: за один стендовый заход снять ВСЁ, что закрывает открытые пункты по колёсам, чтобы не
бегать к железу многократно. Метод — P1-логгер-подход (SWD-снимки в файл на малине, НЕ стриминг;
см. memory p1-logger-service). Каждый пункт: адрес → что читать → зачем.

Контекст-поправка: SPI-slave колёс = прошивка **FU6832N** (не A4963). Значит `MISO=0xFFFF` под
нашей fw = FU6832 не отвечает. Заводской SPI1_DATA в момент вращения покажет, что отвечает ЖИВОЙ
FU6832 — это эталон для нашей отладки. Даташит A4963 больше не источник семантики.

---

## БЛОК 1 — статические RAM-снимки (target остановлен/halt, любой момент после init)

Читать как слова (LE). Указатели → затем deref объекта.

| Адрес | Что | Ожидание | Зачем |
|---|---|---|---|
| `0x20000540` | ptr BLADE a4963-объект | ≠0 | база для reg-блока ножа (base+0x28) |
| `0x2000054c` | ptr LEFT-объект | ≠0 | база LEFT (reg-блок base+0x30) |
| `0x2000057c` | ptr RIGHT-объект | ≠0 | база RIGHT (reg-блок base+0x30) |
| `*0x20000580` | SPI1 init-once флаг | 0 (инициализир.) | доказать, что SPI1 поднят |
| `[LEFT]+0x30..0x3e` | теневые reg0..reg7 LEFT | см. ниже | ЧТО завод реально записал в колёсный FU6832 |
| `[RIGHT]+0x30..0x3e` | теневые reg0..reg7 RIGHT | см. ниже | то же для правого |
| `[BLADE]+0x28..0x36` | теневые reg0..reg7 ножа | эталон (живой) | сравнить с колёсными |
| `[LEFT/RIGHT]+0x22` | byte состояние (0xFF=dir unknown?) | — | состояние драйвера |
| `[LEFT/RIGHT]+0x18/+0x08/+0x10` | флаги | 2/1/1 | целостность объекта |

**Теневые reg — ЭТАЛОННЫЕ значения из дампа (проверить, совпадают ли live):**
- fast-набор LEFT/RIGHT: reg0..5 = `03E8 22DF 4753 6721 8735 A736`, reg7=`EE0D`, reg6(не шлётся)=`C000`.
- slow-набор: reg0..5 = `01A8 2ADF 47D3 6721 8745 A736`.
- **★ Ключ выбора fast/slow = `FUN_08050578()[0x54]` (вариант платы 0/2 vs 1/3).** Снять live-значение
  этого байта → так узнаем, fast или slow завод реально шьёт на ЭТОЙ плате. Наша fw жёстко fast
  (motor.c s_a4963_cfg); A/B fast/slow уже в рантайме с коммита bed655f — этим и проверить.

## БЛОК 2 — SPI1 периферия (base 0x40003800), снять live

| Адрес | Рег | Зачем |
|---|---|---|
| `0x40003800` | SPI1_CTL0 | сравнить с нашим 0x0B2F (hal.c). Полное совпадение? |
| `0x40003804` | SPI1_CTL1 | режим, DMA, NSS |
| `0x40003808` | SPI1_STAT | busy/rxne |
| `0x4000380C` | SPI1_DATA | ★ последнее принятое 16-бит слово = diag ЖИВОГО FU6832 (снять сразу после verify-транзакции; старшие биты = статус). Эталон против нашего 0xFFFF |

## БЛОК 3 — TIMER2 (PWM, base 0x40000400), снять В МОМЕНТ вращения колёс

Колёса на весу, нож снят, старт с базы в «косить». Снять полностью, не только CHxCV:

| Рег (offset) | Зачем |
|---|---|
| CTL0 `+0x00`, CTL1 `+0x04` | counter enable, режим |
| CHCTL0 `+0x18`, CHCTL1 `+0x1C` | режим каналов (PWM mode), preload |
| CHCTL2 `+0x20` | ★ output-enable битов каналов (CH2/CH3 колёс, CH1 нож) — CCR≠0 бесполезен при выключенном выходе |
| PSC `+0x28`, CAR `+0x2C` | частота/период |
| CH1CV `+0x38` (нож), CH2CV `+0x3C` (прав), CH3CV `+0x40` (лев) | duty каждого канала |
| DMAINTEN `+0x0C`, AFIO remap (см. GPIO-map) | полнота |

Сравнить с нашей fw при ненулевом duty. Дельта в CHCTL2/CTL0 = кандидат «почему не крутит».

## БЛОК 4 — GPIO-хореография старта (за 1–2 с до вращения)

Снять IDR/ODR портов, которые мы НЕ реплицируем полноценно: **GPIOC, GPIOE, GPIOF** (+ D для CS/NSS).
Метод: серия снимков ODR всех портов в переходе idle→drive. Ищем ногу, что переключается
одновременно с началом вращения = кандидат на аппаратный ключ питания FU6832-каналов.
Опора: `measurements/force-capture-2026-07-06.txt`, `reference/FACTORY-GPIO-PERIPHERAL-MAP.md`.

## БЛОК 5 — BMS/USART2 (закрыть заодно)

- Connect-кадр уже известен: `1C A1 03 C1 01 2E` (factory-map/03-fsm §2). Проверить в RAM
  буфере USART2 (`0x200005e0` район — 6 байт connect-запроса) live-подтверждение.
- Снять, поднимается ли VBB колёс при активном keep-alive (CE→connect→C3+53). Но по декомпилу
  ЯВНОЙ «enable discharge FET» команды НЕТ (03-fsm §6, 05-bms) — вероятно, разрядный ключ держит
  сам пак по wake. Это согласуется с гипотезой «мёртвый линк гейтит колёса».

## ГЛАВНАЯ РАЗВИЛКА (её решает мультиметр на VDD5, БЛОК не-SWD)

До/параллельно SWD: замерить «5V»(=VDD5 внутр.LDO) на гребёнках Л/П колёс vs нож
(завод idle / завод едет / наша fw). Это первичный сортировщик:
- **колёса VDD5=0, нож=5V** → FU6832 колёс НЕ запитан. SWD-блоки 2/3 вторичны, главное — БЛОК 4
  (GPIO-ключ) + БЛОК 5 (BMS). Ищем, чем завод подаёт VCC на колёсные чипы.
- **колёса VDD5=5V** → чипы запитаны, молчат по протоколу/конфигу. Главное — БЛОКИ 1/2/3
  (reg-набор fast/slow, SPI CTL, TIMER2 output-enable). Реверс «включения» = реверс конфига.

Порядок стенда: (1) VDD5-замер щупами 10 мин → выбрать ветку; (2) SWD-заход по нужным блокам;
(3) при необходимости замер «на ходу» с подпайкой.
