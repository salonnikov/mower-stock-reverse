## ТЕКУЩЕЕ СОСТОЯНИЕ ФЛЕША (проверено чтением)
Залита **валидная RC-прошивка** (образ консистентен):
- hook `0x08053b0e` = `bl 0x08090000` (наш veneer). payload `0x08090000` = veneer. CRC `0x080ffffc` = `fd0f0f91` (target).
- heartbeat дошёл до 0x8ae (наш hook исполнялся ~2222 раза) — код РАБОТАЕТ.
- НО после `reset run` косилка ушла в **E88** и застыла. Гипотеза (обоснована строками прошивки
  «bdboard disconnect / power on overtime / process deal overtime»): E88 = overtime-ошибка связи с
  подсистемами (chip2/дисплей), рассинхроненными из-за `reset run` (сброс ТОЛЬКО ядра). НЕ доказано, что виновата наша прошивка.

## УРОКИ ЭТОЙ ЗАЛИВКИ (учтено в cfg/плане)
1. **wdg-freeze ТОЛЬКО прямой** `mww 0xE0042004 0x00000300` (вариант с `[expr {$cr(0)|0x300}]` в конфиге ПАДАЛ
   с usage-ошибкой → watchdog не морозился → IWDG сбрасывал посреди flash → брик). Все готовые cfg уже с прямым.
2. **НЕ `reset run` для проверки прошивки** — он рассинхронит дисплей/платы → E88/overtime/power-off.
   Для чистого старта — **полный power-cycle физически** (все платы сбрасываются вместе).
3. **Косилка засыпает** при простое/ошибке → chip1 гаснет (DPIDR deadbeef / все нули по SWD). Не путать «уснула»
   с «брик»: при живом питании DPIDR=0x2ba01477.
4. Флеш-обрыв обратим (catch-and-hold доказан): поймать в окне питания (`openocd -f hold.cfg` в цикле, юзер
   держит кнопку) → дожать. bank0-страница с кодом hs-loop → писать ТОЛЬКО под halt.
