# План 2026-07-13: косить (chip2+катушки) ∥ замеры (FU6832) ∥ реверс включения колёс

Контекст-открытие: привод физически = **три Fortior FU6832N** (умный BLDC-контроллер, 8051+FOC,
своя прошивка 16кБ), никаких A4963 на плате нет. «A4963-протокол» реализует прошивка FU6832
(SPI slave: P0.5/SCLK, P0.6/MOSI, P0.7/MISO). Реверс SPI со стороны chip1 остаётся валиден.
У каждого FU6832 — 5-пин гребёнка (подписано 5V/GND + 3 сигнала). По даташиту FU6832
(scratchpad/fu6832_full.pdf): отладка FICE = FICEK на пине **RSTN** + FICED на **P1.2**;
**VDD5 = выход ВНУТРЕННЕГО LDO** (VCC 5–28V) ⇒ наличие 5V на гребёнке = «чип запитан».
Плата под лаком; доступны только разъёмы, гребёнки, тест-пады (можно паяться к пятакам).

Приоритет пользователя: **сначала КОСИТЬ** (собрать косилку на заводской прошивке с новыми
катушками границы), замеры — параллельно, реверс — фоном.

## Трек A (приоритет): завод + новые катушки границы → косить

Факты: chip2 = GD32F4xx bdboard, ADC+DMA, конфиг «base voltage» (деф. 2048 = смещение середины
шкалы, НЕ усиление), окна захвата 800/235 сэмплов, детекция wave/area, результат → chip1 по
UART/cJSON. Одна старая катушка порублена ножом; новые две — другого номинала ⇒ другая
амплитуда/резонанс сигнала.

### A1. Оффлайн (без железа, можно сразу)
- В декомпиле chip2 (`reverse-v2/chip2/decompiled_all.c`) проследить: откуда приходит
  «base voltage» (flash-конфиг? команда chip1? константа) и где пороги детекции wave/area
  (`follow_border_check_wave`, `check_wave`, `follow_check_subwave`). Выход: список
  «ручек чувствительности» с адресами (константы в flash / RAM-переменные).
- В chip1 (bdport, `deal_message.c`) — посмотреть, шлёт ли он chip2 какой-либо конфиг
  (кроме `start search border` / `reset` / версии). Если конфиг существует — это самый
  чистый путь подстройки.
- Учесть: chip2 гоняет **IEC60730 FLASH-CRC32 self-test** ⇒ любой патч прошивки chip2
  требует пересчёта/нейтрализации CRC — проверить, как считается (по дампу есть всё).

### A2. Стенд: измерить, что chip2 реально видит с катушек
- Метод замера — **SWD в chip2** (как делали дамп), лучше через P1-логгер-подход (не стриминг):
  читать RAM-буфер сэмплов (800/235) и результат wave/area.
- Эталон: старая уцелевшая катушка у провода периметра (база включена) → снять уровни.
- Затем новая катушка в той же позиции → снять уровни. Разница амплитуд = коэффициент компенсации.

### A3. Решение по результату A2 (от простого к сложному)
1. **Аппаратно на разъёме катушки** (вне лака!): если приёмный контур резонансный, подстроить
   параллельным конденсатором прямо на разъёме/проводах катушки до максимума амплитуды;
   либо делитель/последовательный резистор, если сигнал наоборот велик.
2. **Конфиг**, если A1 найдёт канал конфигурации (base voltage / пороги) — задать корректное.
3. **Патч порогов chip2** (крайний случай): править пороги в прошивке + решить вопрос CRC32.
- Проверка: lift-сенсоры = «none» (chip2 их же шлёт), chip1 находит границу
  (`bdboard find border`), search/follow работает. Потом сборка и покос.

## Трек B (параллельно, мультиметр): гребёнки FU6832 + тест-пады

Подготовка: макрофото каждой гребёнки (подписи пинов могут быть на шёлке — на фото №1 видны
только 5V/GND, снять остальные три). **Ножевой канал = живой эталон** — сравниваем колёсные
гребёнки с ножевой попарно, пин к пину, даже не зная назначения пинов.

Состояния:
- **S1** — завод, idle (на столе).
- **S2** — завод, реально едет (старт с базы «косить»; колёса на весу, НОЖ СНЯТ/заблокирован!).
  Для S2 полезно заранее припаять провода к нужным падам/пинам — на ходу щупами не попасть.
- **S3** — наша прошивка (rc_fw), команда drive (колесо должно бы крутиться, но молчит).

Замеры (DC, относительно GND гребёнки):
| Точка | Ожидание | Что говорит результат |
|---|---|---|
| «5V» (=VDD5) на гребёнке ножа | 5.0V во всех S | подтверждение методики |
| «5V» на гребёнках Л/П колёс | **ГЛАВНЫЙ ЗАМЕР** | 0V в S1/S3, 5V в S2 → питание каналов гейтится, ищем ключ (→ Трек C4). 5V везде → чипы запитаны, дело в конфиге/протоколе (→ C1–C3). 0V даже в S2 → ошибка методики/пин не VDD5 |
| 3 неизвестных пина, все 3 гребёнки | RSTN ≈ VDD5 (подтяжка); данные ~0/5 | колёсный RSTN=0 при ноже=5 → чипы держат в сбросе (новая ветка) |
| Пады 20V, 20V_BATT, 5V, 3V3 | по номиналу | карта рейлов; 20V vs 20V_BATT в S1/S3 — есть ли отдельный коммутируемый мотор-рейл |
| Пад STOP | ? | понять логику стоп-цепи |
| LEFT_I / RIGHT_I / BLADE_I | ≈0 в покое | опорные точки токовых шунтов (пригодится позже) |

Порядок: 20 минут S1+S3 щупами → уже развилка всего дерева. S2 — вторым заходом (подпайка).

## Трек C (фон, оффлайн + один SWD-заход): как завод включает колёса

База: `reports/WHEELS-ROOT-CAUSE-AUDIT-2026-07-10.md` — открытые пункты остаются, теперь с
поправкой «slave = прошивка FU6832, даташит A4963 не аргумент».

1. **С завода live (P1-логгер, один заход):** platform[0x54] (fast/slow выбор),
   фактические CONFIG0..7 обоих колёс после init (RAM bring-up, см.
   `reference/A4963-DRIVER-bringup-ram.md`), SPI1 CTL0/CTL1/STAT, полный TIMER2
   (CTL0/CHCTL0..2/PSC/CAR/CHxCV/remap) в момент физического вращения колёс.
   Заодно: 6 недостающих байт BMS connect-запроса @0x200005e0 (см. bms-usart2-spec).
2. **Дифф против mower-own** (motor.c: s_a4963_cfg fast-набор жёстко; hal.c: CTL0=0x0B2F) →
   привести к байтовому совпадению. A/B fast/slow уже в рантайме (коммит bed655f) — использовать.
3. **GPIO-хореография старта:** по force-capture + FACTORY-GPIO-PERIPHERAL-MAP найти, какие ноги
   chip1 меняет в момент «колёса начали крутиться» (за 1–2 сек до) — кандидат на ключ питания
   каналов. Особо: ничего ли не дёргается на портах C/E/F, которые мы не реплицируем.
4. **BMS B0..B4 / discharge:** если B-замер покажет гейтинг VDD5 — реверсить, каким событием
   завод включает силовой рейл (BMS-команда? GPIO-ключ 20U?), и повторить его в rc_fw.

Ветвление по итогу B: «питание гейтится» → C4 главный; «питание есть» → C1–C3 главные.

## Правила (напоминание)
- Железо — только по «go»; всё готовить оффлайн заранее; косилка засыпает.
- Тестить ОБА колеса + нож; ВСЕГДА verify флеша (DPIDR≠deadbeef); reset run роняет target —
  только физический power-cycle.
- S2 (езда) — нож снять. Катушечные эксперименты — база включена, периметр замкнут.
