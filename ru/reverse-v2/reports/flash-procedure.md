# Процедура заливки своей прошивки + восстановление (chip1 GD32F305)

Всё ниже **проверено живьём на стенде 2026-07-03** (включая полный цикл брик→восстановление). Инфра: малина `pi@192.168.10.81`, SWD bitbang, openocd 0.10, скрипты в `tools/bench/` (на малине `~/mower-bench/`, конфиги `~/mower-swd/`).

## 0. Железо/сеть — уроки
- **Wifi малины нестабилен** → ВСЕ операции с флешем гонять **detached на малине** (`nohup`), ssh — только запуск+опрос. Обрыв ssh не прерывает.
- Косилка **авто-выключается** после ошибки/простоя и при краше приложения (power-latch). Для заливки — держать питание (зарядка/разбужена), иначе отключение посреди записи = риск.
- **`reset run` сбрасывает только ядро** → рассинхрон дисплея (PIN не вводится). Лечится **полным power-cycle**. Для восстановления после записи предпочтительнее `resume` (RAM не порчен) либо полный power-cycle.

## 1. Раскладка флеша (проверено дампом)
- Загрузчик `0x08000000..0x08017FFF`; его CRC-слово в `0x08017FFC` (boot-гейт, отдельный).
- **Приложение `0x08018000..0x080ffffc`**; код реально до ~`0x08090000`, дальше `0xFF`.
- **Свободно под payload: `0x08090000..0x080ffff8`** (~450 КБ, всё 0xFF).
- **`0x080ffffc` = CRC всего образа приложения** (см. §2).
- ⚠️ dual-bank: 0x08000000..0x0807FFFF = bank0 (openocd stm32f1x пишет), 0x08080000..0x080FFFFF = bank1 (только через FMC bank1, см. §3).

## 2. 🔑 Сквозной CRC образа приложения (КРИТИЧНО)
Приложение защищено HW-CRC-32 над **всем** своим образом (включая пустой хвост):
```
CRC = crc32_stm32(0x08018000 .. 0x080ffffc)
      poly=0x04C11DB7, init=0xFFFFFFFF, 32-битные слова LE, MSB-first, без реверса, без финального XOR
хранится в: 0x080ffffc (последние 4 байта флеша)
эталон стокового образа: 0x0f69a878 (совпал с расчётом = механизм подтверждён)
```
**Любой изменённый байт в 0x08018000..0x080ffffc без обновления CRC → приложение крашится на старте (брик-луп).** Это НЕ обходится — CRC надо **пересчитывать** при каждом патче.

**Рецепт заливки payload (без кирпича):**
1. Записать payload в свободный регион `0x08090000..0x080ffff8`.
2. Пересчитать CRC над `0x08018000..0x080ffffc` (с payload на месте, старый маркер в расчёт входит как есть — считаем до 0x080ffffc НЕ включая сам маркер... **важно**: диапазон заканчивается на 0x080ffffc, т.е. маркер НЕ входит в CRC; проверить границу при реализации).
3. Записать новый CRC в `0x080ffffc`.
4. Загрузка проходит.

> Payload в bank1 (≥0x08080000) → писать через FMC bank1 (§3). Маркер 0x080ffffc тоже в bank1.

## 3. Запись флеша
**bank0 (0x08000000..0x0807FFFF):** openocd `stm32f1x`, но размер банка задавать ЯВНО:
`flash bank chip.flash stm32f1x 0x08000000 0x100000 0 0 chip.cpu` (autodetect по id 0x418 врёт 256К).
Нужен work-area: `target create ... -work-area-phys 0x20000000 -work-area-size 0x2000`.

**bank1 (0x08080000..0x080FFFFF):** openocd stm32f1x НЕ умеет → через **FMC bank1 напрямую** (адреса из вендорного SVD):
- KEY1=`0x40022044` (unlock: 0x45670123, затем 0xCDEF89AB)
- STAT1=`0x4002204C` (bit0 BUSY), CTL1=`0x40022050` (PG=1,PER=2,MER=4,START=0x40,LK=0x80), ADDR1=`0x40022054`
- **erase page:** unlock; CTL1=PER; ADDR1=addr; CTL1=PER|START; ждать BUSY=0; CTL1=0.
- **program halfword:** CTL1=PG; `mwh addr val16`; **ждать BUSY=0 (опрос STAT1) после КАЖДОГО**; CTL1=0. (без ожидания BUSY openocd `mwh` ретраит и пишет мусор → 0x00.)
- lock: CTL1=LK.
Пример: `tools/bench/flash_bank1_v2.cfg` (tcl-процедуры с BUSY-опросом).

**Общее для всех записей:** halt + заморозить watchdog: `mem2array cr 32 0xE0042004 1; mww 0xE0042004 [expr {$cr(0)|0x300}]` (иначе IWDG/WWDG сбрасывает при halt).
Защита: FMC_WP `0x40022020` = 0xFFFFFFFF (write-protect нет). RDP: не level-2 (чтение работает). unlock/mass_erase НЕ запускать.

## 4. Откат (проверено)
Полный дамп-откат: `dist/gd32-mainboard-dump-v1.bin` (sha256 82b8bb5a...), == текущему флешу == 2 дампа на малине. Восстановление = записать дамп обратно (bank0 stm32f1x + bank1 FMC).

## 5. Восстановление из «не грузится» (проверено end-to-end)
Если после записи косилка не грузится (дисплей→бегунок→гаснет = краш до power-latch, chip1 не виден по SWD т.к. питание отваливается):
1. **catch-and-hold ловушка:** `tools/bench/hold.cfg` + цикл `hold_loop.sh` (`while: openocd -f hold.cfg` БЕЗ timeout — на успехе openocd блокируется и держит halt). Пользователь **ДЕРЖИТ кнопку включения** (окно питания).
2. Как поймали (`:4444` UP) — читать/чинить через держащий openocd (telnet :4444, `rdmem.py`, `fmc_erase.py`).
3. Стереть/восстановить нарушенный регион → флеш==дамп (или консистентный образ с верным CRC).
4. Полный **power-cycle** косилки.
Если ловушку надо убить на малине, а wifi рвётся — **`sudo reboot` малины** (чисто, poll.cfg сам поднимется). NB: `pgrep -f hold_loop` ловит сам себя — считать `ps -eo args|grep -c "[/]tmp/hold_loop"`.

## Инструменты (tools/bench/)
swd.py (клиент :4444), rdmem.py (чтение), flash_run.sh (detached-раннер cfg), flash_bank1_v2.cfg (bank1 write с BUSY), fmc_erase.py (bank1 erase), hold.cfg/hold_loop.sh (catch-and-hold), flash_dump.py (дамп).
