# TIMER0 — оффлайн-разбор (2026-07-07). ВЕРДИКT: лид МЁРТВ.

Гипотеза сессии (из handoff): TIMER0 (advanced, 0x40012C00) гонит charge-pump/gate-drive
для high-side ключа коммутируемого рейла 20U колёс; завод его конфигурит, наша fw держит idle.
**Проверено оффлайн (дамп + декомпиляция), без железа. Гипотеза НЕ подтвердилась.**

## Метод
- Наша fw: `hal.c` включает только TIMER2 (`RCU_APB1EN |= TIMER2EN|SPI1EN`); TIMER0 не трогает
  вообще ⇒ наш TIMER0 = то, что оставил бутлоадер (общий с заводом). Отличаться может только
  если TIMER0 конфигурит заводское **приложение**.
- Заводской дамп `dist/gd32-mainboard-dump-v1.bin`: байт-скан выровненных литералов баз таймеров.
  Любой доступ к TIMER0 обязан материализовать базу 0x40012C00 (обычно literal-pool).
  Найдено **8** выровненных литералов `00 2c 01 40`. Все сопоставлены с функциями декомпиляции.
  (Калибровка: TIMER2=31, TIMER1=12, TIMER3=16, TIMER4=6 — все используемые таймеры видны.)

## Куда ведут 8 литералов TIMER0
| flash | владелец | что это |
|---|---|---|
| 0x08000ee8 | FUN_08000e48 | **бутлоадер**: `timer_deinit(TIMER0)` + `timer_deinit(TIMER1)` (общий с нами) |
| 0x08009ed0/ef8/e5c | FUN_08009e60 / e3c | **единственная реальная app-конфигурация** TIMER0 |
| 0x080121a0 | FUN_08012170 | GD32 timer-lib (advanced-спец-кейс, `==`-константа) |
| 0x08012248 | FUN_080121d0 | `timer_init` — advanced-спец-кейс (CREP), `==`-константа |
| 0x0807f640 | FUN_0807f474 | `timer_channel_output_config` — advanced-спец-кейс (compl. outputs), `==` |
| 0x0807f850 | FUN_0807f7d8 | `timer_channel_output_config` companion — advanced-спец-кейс (CREP), `==` |

Библиотечные функции (12170/121d0/f474/f7d8) содержат базу TIMER0 только как **константу
сравнения** для спец-обработки advanced-таймеров (комплементарные выходы, CREP) — они
линкуются независимо от того, используется ли TIMER0. Это не «конфигурация TIMER0».

## Единственная реальная конфигурация TIMER0 = таймер-задержка
`FUN_08009e60(1)` → `timer_deinit` → `timer_init(TIMER0, {PSC, CAR=11999, …})` →
interrupt-enable → `timer_enable(CEN)`. **Никаких channel-output (CHCTL0/1 OCxM), никакого
CHCTL2 channel-enable, никакого CCHP (break/main-output-enable), никакого AF-пина.**
`FUN_08009e3c`: ставит счётчик, стартует TIMER0, busy-wait `while(*counter!=0)`, затем гасит CEN.
⇒ **TIMER0 = периодический interrupt-таймер, используемый как блокирующая задержка. Не PWM, не gate-drive.**

## Контрольный удар: мотор-драйвер не использует TIMER0
`FUN_0805aee0` = **left-motor driver init** (`lmdrv`; грузит A4963 reg0..7, reg7=0xEE0D).
Резолвленные таймер-базы:
- `DAT_0805b144 = 0x40000400` = **TIMER2** → `timer_channel_output_config(TIMER2, ch3)` = LEFT PWM ✓ (совпадает с картой)
- `DAT_0805b148 = 0x40000800` = **TIMER3** → канал 1 = тахо/одометрия LEFT
- `0x2000054c` = RAM-структура драйвера; `0x0805fdc9/fdbd/fbc1/fd45` = коллбэки (Thumb-адреса, не базы)

**TIMER0 в мотор-драйвере отсутствует.** Мотор-путь = TIMER2 (PWM) + TIMER3 (одометрия).

## Вывод
**TIMER0 НЕ относится к силовому пути колёс.** Он — отдельный таймер-задержка. Гипотеза
«TIMER0 charge-pump’ит гейт 20U» опровергнута двумя независимыми путями (нет каналов/CCHP в
его конфиге; мотор-драйвер его не трогает). **Последний firmware-лид закрыт.**

### Оговорки (малая остаточная неопределённость)
1. Байт-скан ловит literal-pool; `movw/movt`-загрузку базы он бы пропустил. Но GD32-либа явно
   использует literal-pool (8 попаданий), и мотор-драйвер TIMER0 не трогает — оба независимы от этой оговорки.
2. Пара TIMER0-выходных пинов (PA10/11, PE11/13/14) не была в живой GPIO-таблице state5.
   Но при езде PE9 = plain OUT-LOW (не AF), TIMER0-каналы в коде не сконфигурены ⇒ AF-выхода нет.

## Следствие для плана
Все firmware-авеню включения рейла 20U исчерпаны (GPIO / periph-enable / SPI-арм / пак-опрос /
**TIMER0**). Остаётся **железо**:
- (A) high-side ключ рейла 20U (Q10/Q17/Q14) — прозвон гейта завод-на-ходу vs наш; чем он реально включается.
- (B) discharge-FET силового мотор-тапа в **батарейном паке** — включается ли устойчивым BMS-протоколом (USART2), которого мы не досатисфицировали. Нож на отдельном (живом) тапе — потому крутится.
