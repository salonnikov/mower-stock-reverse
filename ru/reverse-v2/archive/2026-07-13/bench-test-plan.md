# Стендовые испытания привода — синхронизированный протокол (софт ↔ железо)

Цель: **живьём** установить, что физически вращает колесо (PWM-duty CH3CV и/или состояние A4963 по SPI), не разрушая косилку и без рассинхрона между софт-действиями (SWD) и физическими действиями с косилкой.

Принцип (чтобы не повторять прошлые косяки):
- **Всё готовится ДО начала.** Ни одной команды не сочиняем в процессе — все ниже, копипастой.
- **Строгая очередь ходов.** Каждый шаг помечен: `[ТЫ-ЖЕЛЕЗО]` (физическое действие пользователя) / `[Я-СWD]` (моя команда по SWD) / `[СМОТРИМ]` (наблюдение+решение). Следующий шаг не начинаем, пока предыдущий не подтверждён вслух («сделал», «вижу N»).
- **Каждый шаг — GO/NO-GO.** Если наблюдение не совпало с ожиданием — СТОП, разбираемся, не идём дальше.
- **Пишем, не думаем.** Думанье — сейчас, в этом документе. На стенде — только исполнение.

---

## 0. Роли
- **ТЫ (железо):** стенд, питание, физическое наблюдение вращения, аварийный СТОП рукой/питанием. Голосом подтверждаешь каждое действие и что видишь.
- **Я (софт/SWD):** через OpenOCD (:4444 на малине) читаю/пишу память и регистры chip1, логирую. Ничего не пишу во флеш. Только RAM/периферия, всё откатываемо снятием питания.

## 1. Железо — предусловия (ДО старта)
1. **Ведущие колёса вывешены** (подставка/коробка), крутятся свободно, ничего не заденут.
2. **Нож физически отключён** (снять/отсоединить разъём мотора ножа). Не полагаемся на софт-disable.
3. **Питание стабильное:** косилка на зарядке ИЛИ заряженный АКБ; малина от повербанка (не от косилки).
4. **SWD подключён** к chip1 (проверенная распиновка из прошлых сессий).
5. Рядом — способ мгновенно обесточить (рука на разъёме питания/выключателе).

## 2. Софт — предусловия (ДО старта)
1. `mower-openocd` поднят (:4444). **`mower-webctl` ОСТАНОВЛЕН** на время теста (OpenOCD — один telnet-клиент): `sudo systemctl stop mower-webctl`.
2. Я подключаюсь к OpenOCD: `telnet 127.0.0.1 4444` (через малину).
3. **НЕ делаем `halt`** без явного решения — halt останавливает RTOS, A4963 может уйти в fault/сброс, и тест исказится. Работаем по «живому» (on-the-fly чтение/записьOpenOCD умеет без halt через AHB-AP).

## 3. Опорные адреса (chip1)
| Что | Адрес | Прим. |
|---|---|---|
| state | `0x200000bc` | 3=idle,4=departure,5=cutting,6=findbd,7=dock,8=charge,9=err,10=off |
| movebase-синглтон | `*0x20000338` | 0 если сервис не поднят |
| TIMER2 CTL0 (CEN) | `0x40000400` | бит0=CEN (счётчик идёт) |
| TIMER2 CHCTL2 (вкл. каналов) | `0x40000420` | CH3EN и полярность |
| TIMER2 CAR (период) | `0x4000042c` | ожидаем ~0x1c20=7200 |
| TIMER2 CNT | `0x40000424` | должен бежать, если CEN=1 |
| **TIMER2 CH3CV (duty ЛЕВОГО колеса)** | **`0x40000440`** | сюда пишет set_left; наш объект теста |
| TIMER2 CH2CV | `0x4000043c` | второй канал (правое? — подтвердить live) |
| A4963 SPI: тело set_left | `FUN_0805f620` | не вызываем, для справки |

> Правое колесо — тоже TIMER2, канал уточним в Фазе 0 живым чтением (какой CHxCV меняется при штатной езде).

## ФАЗА 0 — Пассивная разведка (НИКАКИХ записей) — GO/NO-GO
Цель: узнать реальное живое состояние, прежде чем что-то трогать. Это отсекает «слепые» записи.

- **[ТЫ-ЖЕЛЕЗО]** Разбуди косилку в обычное включённое состояние (как перед стартом кошения), но **НЕ** давай команду «косить/домой». Скажи, в каком состоянии по экрану.
- **[Я-СWD]** Читаю: `state`, `*0x20000338`, TIMER2 `CTL0/CHCTL2/CAR/CNT/CH3CV/CH2CV`.
- **[СМОТРИМ]** Ожидание/решение:
  - Если `*0x20000338 == 0` → движ-сервис не поднят, A4963 не сконфигурен → **PWM бессмысленно тестировать**, сперва поднять сервис (Фаза 1a). 
  - Если `CTL0.CEN==0` или `CH3EN==0` → таймер/канал не активны → запись CH3CV ничего не даст; фиксируем и переходим к варианту через состояние.
  - Если `CNT` не меняется между двумя чтениями → таймер стоит.
  - `CH3CV` текущее значение и `CAR` — записываем как baseline.
- **Результат Фазы 0:** знаем, активен ли PWM-тракт в текущем состоянии. GO дальше только с этим знанием.

## ФАЗА 1 — Калибровка одометрии (руками, без моторов) — GO/NO-GO
Цель: найти живой счётчик тиков колеса (он в malloc-RAM, адрес плавающий), чтобы в след. фазах измерять вращение объективно, а не «на глаз».

- **[Я-СWD]** Делаю снимок RAM-региона движ-данных (вокруг `*0x20000338` pri_data, ~0xA4 байт) — значение №1.
- **[ТЫ-ЖЕЛЕЗО]** Медленно проверни ЛЕВОЕ колесо рукой ровно N оборотов (скажем 10), скажи «готово».
- **[Я-СWD]** Снимок №2 того же региона. Ищу поле, выросшее монотонно.
- **[СМОТРИМ]** Нашли счётчик тиков левого колеса (адрес X_L) и грубый коэффициент тик/оборот. Повторяем для правого (адрес X_R). 
  - Если счётчик не найден в pri_data — расширяю скан (тахо на TIMER3 capture: читаю `TIMER3 CNT`/каналы `0x40000824/…`).
- **Результат:** есть живые адреса тиков X_L/X_R. Теперь вращение измеряемо числом.

## ФАЗА 2 — Пассивное наблюдение PWM (читаем, не пишем) — GO/NO-GO
Цель: понять, переписывает ли прошивка CH3CV сама (и как часто), чтобы выбрать метод инъекции.

- **[Я-СWD]** В текущем (не-режущем) состоянии читаю `CH3CV` многократно (несколько раз за секунду, ~10с).
- **[СМОТРИМ]**
  - CH3CV **стабилен** (не меняется) → прошивка сейчас его не трогает → **можно писать напрямую, запись удержится** → Фаза 3 (прямая запись).
  - CH3CV **дёргается** сам → контур активно командует → прямая запись будет затираться каждые ~10мс → нужен другой путь (Фаза 4: влиять на вход контура/через состояние), либо писать в цикле.
- **Результат:** выбран метод инъекции.

## ФАЗА 3 — Прямая запись CH3CV (главный тест) — по одному колесу, малыми шагами
Предусловие GO: Фаза 0 показала CEN=1 & CH3EN=1 & движ-сервис поднят; Фаза 2 показала, что CH3CV стабилен (не перезаписывается) ИЛИ мы пишем в цикле.

- **[ТЫ-ЖЕЛЕЗО]** Подтверди: колёса вывешены, нож отключён, рука на аварийном обесточивании. Скажи «готов».
- **[Я-СWD]** Пишу **малый** duty в левый CH3CV: `mww 0x40000440 500` (≈7% от CAR 7200). Сразу читаю X_L дважды с интервалом.
- **[СМОТРИМ]** 
  - Тики X_L растут И **[ТЫ-ЖЕЛЕЗО]** видишь/слышишь вращение левого колеса → **PWM-duty РЕАЛЬНО крутит** ✔ (гипотеза подтверждена живьём).
  - Тиков нет и колесо стоит → duty сам по себе НЕ крутит → значит нужен ещё A4963 (Фаза 4).
- **[Я-СWD]** Возврат: `mww 0x40000440 0`. **[СМОТРИМ]** колесо тормозится/встаёт? (проверка «CH3CV=0 = тормоз»).
- Повтор с бОльшим duty (1000, 2000) только если малый прошёл чисто и безопасно. Наращиваем медленно.
- **АВАРИЯ:** любое неожиданное поведение (рывок, вой, нагрев, не тот канал) → **[ТЫ-ЖЕЛЕЗО]** обесточить; я пишу 0 во все CHxCV.

## ФАЗА 4 — Роль A4963 (если Фаза 3 не закрутила)
Цель: проверить, нужен ли доп. SPI-шаг (RUN/direction/gear) поверх PWM.
- **[Я-СWD]** Читаю живые теневые A4963-регистры драйвера левого мотора (найду через движ-структуру) — проверяю, RUN=1 ли сейчас.
- **[СМОТРИМ]** Если RUN не выставлен в текущем состоянии → движ-сервис не инициализировал мотор в этом состоянии; переводим косилку в состояние, где мотор поднят (departure/manual), повторяем Фазу 3.
- (Прямую запись A4963-регистров по SPI из SWD НЕ делаем на этом этапе — сначала исчерпываем безопасные варианты через состояние.)

## Критерии немедленного СТОПа
- Двигается НЕ то колесо / оба сразу неожиданно.
- Любой посторонний звук, вибрация, запах, нагрев.
- Тики растут, а команда была 0 (потеря контроля).
- Косилка меняет состояние сама (ушла в departure/cutting) → значит поймали авто-старт: обесточить, вернуться, в след. раз глушить авто-старт (не входить в 4/5/6).

## Что НЕ делаем в этом тесте
- Не пишем во флеш (только RAM/периферия).
- Не делаем `halt` без отдельного решения.
- Не тестируем нож.
- Не входим в state 5/6 (там border-навигация начнёт командовать моторами сама).

### Резюме одной строкой
Разведка (0) → калибровка тиков руками (1) → смотрим, живой ли PWM сам (2) → малым duty пишем CH3CV и по тикам+глазу решаем, крутит ли (3) → если нет, разбираемся с A4963 (4). Каждый шаг — подтверждение вслух и GO/NO-GO.
