## ЦЕЛЬ ПРОЕКТА
Своя прошивка для робота-косилки MI 302: ручное RC-управление + автономка + откат на заводскую + тулзы/инструкции прошивки. chip1 = GD32F305 (главный мозг), chip2 = GD32F30x (плата коилов границы), дисплейная плата (UI).

## КЛЮЧЕВЫЕ ФАКТЫ ДЛЯ ЗАЛИВКИ (всё проверено)
- Флеш chip1: загрузчик 0x08000000..0x08017FFF (его CRC-гейт: слово 0x08017FFC, отдельный).
  Приложение 0x08018000..0x080ffffc, код до ~0x08090000, дальше 0xFF.
- 🔑 **Образ приложения под сквозным HW-CRC-32** (poly 0x04C11DB7, init 0xFFFFFFFF, слова LE, MSB-first,
  без реверса/финXOR) над **0x08018000..0x080ffffc**, CRC хранится в **0x080ffffc**. Стоковый = 0x0f69a878.
  **Любой байт в диапазоне без обновления CRC → брик.** Рецепт: payload → пересчитать CRC → записать в 0x080ffffc.
- **Свободно под payload: 0x08090000..0x080ffff8** (~450К, всё 0xFF).
- **Dual-bank**: bank0 0x08000000..0x0807FFFF (openocd stm32f1x, размер ЯВНО 0x100000!),
  bank1 0x08080000..0x080FFFFF (только через FMC bank1 напрямую).
- **FMC bank1** (из вендорного SVD): KEY1=0x40022044 (unlock 0x45670123,0xCDEF89AB), STAT1=0x4002204C (bit0 BUSY),
  CTL1=0x40022050 (PG=1,PER=2,MER=4,START=0x40,LK=0x80), ADDR1=0x40022054.
- **Метод записи bank1 (НАДЁЖНЫЙ, проверен)**: PG выставить ОДИН раз на страницу, mwh каждое полуслово + sleep 6-8,
  clear PG в конце (см. `flash_proof.cfg`). Per-halfword busy-poll (v2) даёт мусор 0x00 — НЕ использовать.
- **Всегда**: halt + заморозить watchdog `mem2array cr 32 0xE0042004 1; mww 0xE0042004 [expr {$cr(0)|0x300}]`.
  Защита: FMC_WP 0x40022020=0xFFFFFFFF (нет WP), RDP не level-2. unlock/mass_erase НЕ запускать.
- **resume, НЕ reset run** (reset run = только ядро → рассинхрон дисплея, лечится полным power-cycle).
- **Откат**: `dist/gd32-mainboard-dump-v1.bin` (sha 82b8bb5a...) == текущему флешу (кроме proof-payload сейчас).

## ПРИВОД (для будущего hook ручного управления)
- Колёса = 3× BLDC на Allegro A4963 (2 колеса + нож). Скорость→ШИМ TIMER2 (0x40000400):
  **CH3CV 0x40000440 = ЛЕВОЕ, CH2CV 0x4000043c = ПРАВОЕ** (от порта зарядки, подтверждено живьём).
  Направление/тормоз/конфиг → SPI A4963. A4963 в RUN уже с init.
- set_left_motor_speed `FUN_0805f620(dir 0/1, |speed| 0..6141)` объект неявный (глобал 0x2000054c);
  правый `FUN_0806fe66`, объект 0x2000057c. Направление = FUN_0801f4c6. Передача = FUN_0801f4dc.
- Драйвер оживает ТОЛЬКО в ходовом состоянии (state 4/5/6/7). В idle (3) lmdrv/rmdrv=0, A4963 не в RUN.
- state = 0x200000bc (сеттер FUN_0807976c 0..10): 3idle 4departure 5cutting 6findborder 7dock 8charge 9err 10off.
  Программная «кнопка»: `mww 0x200000bc 6` (форс) заводит движение, но грубо (борется с SM).
- Точка hook для RC: process-manager tick / movebase (executor из a9411aa имеет НЕВЕРНЫЕ якоря — переписать
  или писать свой; hook 0x20000078 неверен, RAM 0x2001C000 вне SRAM(96К), UART-адреса пустые).

## ВОССТАНОВЛЕНИЕ ИЗ БРИКА (проверено, если снова)
Симптом: дисплей→бегунок→ГАСНЕТ (краш до power-latch), chip1 не виден по SWD (0xdeadbeef, питание отваливается за доли сек).
1. `recovery.cfg` (init+halt+fix) в цикле `recovery_loop.sh` (openocd БЕЗ timeout → на успехе держит halt).
2. **Пользователь ДЕРЖИТ кнопку включения** ~15с (окно питания) — цикл ловит проц и в один заход чинит флеш
   (стереть нарушенную страницу + восстановить CRC 0x0f69a878 = образ консистентен).
3. Полный power-cycle косилки → чистая загрузка.
Косилка авто-выключается после ошибки/простоя → для заливки держать на зарядке/разбуженной.
