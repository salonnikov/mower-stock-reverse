# План замеров на живой косилке — SWD-only редакция (2026-07-06)

**Оборудование (подтверждено):** только SWD через малину (openocd :4444). Лог-анализатора / осциллографа / мультиметра НЕТ. К пинам GD32/A4963 подлезть **труднодоступно** → физически слушать шину A4963 и мерить VBB НЕЛЬЗЯ.
**Следствие:** пассивный захват шины (старый M1) и замер VBB (M2) — отпадают. Всё строим на том, что SWD читает память и регистры периферии живьём (без halt).
**Зачем:** заводская колёса крутит → железо исправно. Наша прошивка не воспроизводит то, что делает завод. Надо снять целевое СОСТОЯНИЕ, которого завод достигает для езды, и повторить его. Раз шину не снять — читаем внутренности заводского драйвера из дампа + живые регистры.

## Что не знаем → чем закрываем в SWD-only

| Неизвестное | Раньше хотели | Теперь (SWD-only) |
|---|---|---|
| CS-пин ↔ мотор (PD3/4/5 = [I]) | лог-анализатор на CS | **P0: прочитать из asm** — какие gpio_bit_reset/set в SPI-функции драйвера (порт+маска). Байт-точно из кода. |
| enable (правда ли PB12) | LA | **P0** (gpio_bit_set в create) + **P1** (GPIO ODR в drive-состоянии) |
| Последовательность bring-up A4963 | LA-декод | **P0**: разобрать оркестратор (FUN_080477c4 и цепочку) по asm пошагово |
| RUN: фронт или held | LA (reg7 на шине) | **P0** (что пишется в reg7) + **P1** (теневой reg7 в RAM) |
| VBB есть/гейтится, чем | осц на рейл | **P1**: найти GP-выход, встающий HIGH только в drive (косвенно); прямого замера рейла нет |
| «VBB-enable GPIO» (PD10/PE0/PA0/PD7) | LA | **P1**: GPIO CTL/ODR diff idle→drive (чисто, с метками состояний) |
| Что читает MISO у живого A4963 (калибровка 0xFFFF) | LA на MISO | **P0**: найти, куда драйвер кладёт последний прочитанный diag в RAM → **P1** прочитать живьём |
| канал PWM ↔ колесо, duty→скорость | LA на PWM | **P1**: TIMER2 CHxCV в drive при известном манёвре |

## Стратегия

### P0 — ОФЛАЙН из дампа (без железа, СТАРТУЕМ СРАЗУ) ← главный разблокиратор
Раз к шине не подлезть — единственный способ узнать CS/enable/bring-up точно = **прочитать это из кода заводского драйвера**, побайтово, а не по строкам (строк там нет). Достать:
1. **CS: порт + маска на каждый мотор.** В SPI-транзакции A4963 (FUN_080840d8/FUN_0808408c) — какие `gpio_bit_reset(port,mask)` перед кадром и `gpio_bit_set` после. Это и есть настоящие CS. Разрешить конфликт PD5 vs USART1-remap.
2. **Enable-пин(ы):** `gpio_bit_set` в create/init драйвера (FUN_0805aee0 и соседи). Правда ли PB12, есть ли ещё.
3. **Полный bring-up:** оркестратор (FUN_080477c4 и что он зовёт по шагам): init → (power?) → enable → RUN. Что реально в каждом шаге.
4. **RAM-адреса драйвера:** объект(ы) (~0x20000544/0x2000054c и точнее), где лежат теневые конфиг-слова, reg7/RUN, и **последний прочитанный diag** (чтобы в P1 прочитать живой ответ A4963).
5. **reg7/RUN:** пишется RUN=1 с init или фронтом; DIR/BRK/CM.
6. **TIMER2:** какой CHxCV на какое колесо (set_left/set_right), duty→скорость.
Выход P0: точный целевой профиль «пины + слова + RAM-адреса», против которого сверяем и P1, и нашу прошивку.

### P1 — ЖИВОЙ SWD-снимок регистров/RAM по состояниям FSM (когда P0 даст адреса)
Малина, openocd :4444, БЕЗ halt (halt = внешний reset, выбьет из хода). Один batch-скрипт читает весь набор за раз в файл (медленный/флейки wifi — не по одному mdw). Снять в состояниях: **idle-на-базе → departure(4) → на-ходу(5) → error(9)**.
Читаемый набор (адреса — в конце дока): все GPIO CTL0/CTL1/ODR (A..E), AFIO_PCF0, SPI1 CTL0/CTL1/STAT, TIMER2 весь, RCU APB1/APB2/AHB EN, state 0x200000bc, + RAM-адреса драйвера из P0 (теневые regs + diag).
**Что даёт:** какие пины меняются idle→drive (enable/рейлы), значение живого diag A4963, PWM-каналы/duty на ходу, точную периферию → **список дельт против нашей прошивки**.

### P2 — сверка и починка
Собрать целевое состояние (P0+P1) → привести нашу прошивку байт-в-байт (CS/enable/config/AFIO/timer) → тест нашей на вывешенных колёсах.

## ⚠️ Безопасность (до любого «поехать»)
1. **НОЖ физически отключить** (разъём мотора ножа снять). 2. **Колёса вывесить.** 3. Питание с базы (стартует только с зарядки в «косить»). 4. Все замеры **пассивные** — заводскую НЕ перешивать, SWD только чтение, БЕЗ halt. 5. Перемычка л/п коилов — ожидаемый глюк, замеру не мешает.

## Тулчейн (SWD-only) — что готовим
- [ ] P0: офлайн-разбор драйвера (субагенты Fable5) → таблица «CS/enable/bring-up/RAM-адреса». **Запущено.**
- [ ] P1: один openocd-cfg, читающий весь набор регистров в файл, detached-раннер на малине (как flash_run.sh). Набор адресов — ниже.
- [ ] Хостовая сверка снимка с ожидаемыми значениями нашей прошивки (diff-скрипт).
- [ ] Малина жива (192.168.10.81, :4444, дашборд /api/gpio_live уже умеет non-halt).
- [ ] Стенд: подставка (колёса вывесить), нож отключён, база рядом. Способ метить «сейчас idle / сейчас едет».

## Адреса для P1-снимка (GD32F30x)
- GPIO CTL0/CTL1/ISTAT/OCTL (+0x00/+0x04/+0x08/+0x0C): A=0x40010800, B=0x40010C00, C=0x40011000, D=0x40011400, E=0x40011800.
- AFIO_PCF0 = 0x40010004 (ждём заводское 0x00001C30; у нас баг 0x001A0C00).
- SPI1 (0x40003800): CTL0 +0x00, CTL1 +0x04, STAT +0x08.
- TIMER2 (0x40000400): CTL0 +0x00, CHCTL0 +0x18, CHCTL1 +0x1C, CHCTL2 +0x20, PSC +0x28, CAR +0x2C, CH0CV +0x34, CH1CV +0x38, CH2CV +0x3C, CH3CV +0x40.
- RCU (0x40021000): AHBEN +0x14, APB1EN +0x1C, APB2EN +0x18.
- state = 0x200000bc.
- A4963-драйвер RAM (теневые regs + last diag) — адреса из P0.
