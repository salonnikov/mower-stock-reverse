# Сверка: наш reverse-v2 ↔ параллельный аудит из git (коммит a9411aa)

Коммит `a9411aa` («независимый аудит, WP1–WP4, тонкий исполнитель») — вторая, независимая команда сделала свой полный Ghidra-декомпил обоих чипов (`docs/fw/ghidra/`), подсистемные разборы (`docs/fw/decompiled/`) и **уже заготовку прошивки-исполнителя** `firmware/mower-executor/` (mx_vendor/mixer/proto/safety/hook). Их работа аккуратная (есть verification-log, самокритика). Ниже — где сходимся, где расходимся, что взять у них.

Легенда: ✔C наш вывод из кода · ✔D даташит A4963 · ❗ расхождение · 🎁 у них лучше/готово.

## 1. Сходимся (две независимые команды → высокая уверенность)
- chip1=GD32F305 (reset 0x08011a3c, SP 0x20016ed8), chip2=GD32F30x (reset 0x080001b4). ✔C
- `set_main_state 0x0807976c` (кламп 0..10), state=`0x200000bc`. ✔C
- CRC-8 Dallas poly 0x8C @`0x080241d0`. ✔C
- **Левый set_wheel_speed = `0x0805f620`**, финал PWM через `FUN_0807f696`, lmdrv-ctx `0x2000054c`. ✔C (у нас ещё форс-декомпил тела: gear-map speed*0x1c20/gear_max).
- Драйверы моторов зовутся **через vtable сервис-объекта, не по жёсткому адресу** — они это верно зафиксировали (verification-log §C), и это совпало с нашим (set-speed достижима лишь по указателю, дыра статич.графа). ✔C
- Их живой байт-чек `0x0805f9ac = movw 0x5fd(1533)` совпал с нашим gear-константным {1533..6141}. ✔C

## 2. Где reverse-v2 ПОПРАВЛЯЕТ их ❗
**(a) Одометрия `0x2000be28`/`0x2000be58` — у них [OK], на деле НЕ статический анкер.**
Проверка сырых байт: литерал `0x2000be28`/`be58` встречается в бинаре **0 раз** (для контраста `0x2000054c`=9, `0x20000338`=17). → это **malloc-адреса из одного живого бута**, не robust. Их `mx_vendor_read_telemetry` читает их как фикс — **сломается при другом бут-порядке/версии**. Реальный механизм (наш ✔C): тахо A4963 → **TIMER3 (0x40000800) input-capture** → ISR `FUN_0805fbc0`/`FUN_0805fd45`, счётчики в malloc-структуре колеса. → телеметрию тиков брать через движ-объект (`*0x20000338`→pri_data), а не по абсолюту.

**(b) A4963 — у них не разобран; у нас полная регистровая модель (✔D).**
- Скорость = PWM на **TIMER2 CH3** (не serial-demand). RUN=1 уже с init (reg7=0xee0d, ClosedLoopSpeed). По умолчанию duty0% → тормоз/удержание.
- **Направление — ОТДЕЛЬНАЯ функция `FUN_0801f4c6`** (бит DIR reg7), верх — `FUN_0805f300`. `FUN_0801f4dc` = НЕ «brake to dir», а выбор **макс-скорости/передачи** (CONFIG5 SMX: 1533/3069/6141).
- ❗ Их `mx_vendor_drive` зовёт `rotation(obj, speed, dir_hint=0)` **всегда с dir_hint=0** → если родная set_speed не ставит направление сама (а оно отдельное) — **колесо не даст реверс**. Нужно перед скоростью звать set_direction (`FUN_0805f300`/`FUN_0801f4c6`) с нужным знаком.

**(c) Правый мотор.** Они: `right_motor_rotation = 0x0806fce0` (в mx_vendor.h вообще TODO=0). Мы: форс-декомпил `0x0806fe66` = чистое зеркало левого gear-map. Оба в одной дыре right-motor драйвера (0806fce0<0806fe66). → **сверить одним прогоном** какой вход «rotation» vs внутренний расчётчик; дать им подтверждённый адрес.

**(d) Их «второй расчётчик `fcn.08020e0c`»** (гипотеза «второе колесо/нож») — у нас регион 08020e0c оказался НЕ мотор (ближе к калибровке батареи). Правый привод = 0806fxxx, не 08020e0c. ❗ проверить.

**(e) Гейтинг.** Наш ✔C: border-навигация активна **только в state 5/6** (внутри `FUN_08030128`), `manual set` флаг приводом НЕ рулит. → их точка инъекции (WP3, обёртка process-manager) должна учитывать: подавать своё движение вне 5/6, иначе штатный cutting будет спорить за моторы.
