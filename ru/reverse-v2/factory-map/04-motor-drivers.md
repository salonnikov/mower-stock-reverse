# 04 — Мотор-драйверы chip1 (нож / левый / правый) + A4963

Полный разбор трёх A4963-драйверов заводской прошивки MI 302 (chip1, GD32F4xx).
Источник: `reverse-v2/chip1/decompiled_all.c` + дамп `dist/gd32-mainboard-dump-v1.bin`.
Цель: найти асимметрию нож-vs-колёса, кандидаты на «питание/gate колёс».

> **Статус декомпиляции.** Полностью декомпилирован и авторитетен **ЛЕВЫЙ** драйвер
> (`FUN_0805aee0` + run/brake `FUN_0805f2xx..f5xx`). Конструкторы **ножа** (`0805a858`)
> и **правого** (`0805b820`) попали в неразобранные пробелы Ghidra — их поля восстановлены
> по ops-таблицам (function-pointer vtable) и по общим хелперам, которые они реально вызывают.
> Это честно отмечено ниже. Все три мотора используют один и тот же путь записи A4963.

---

## 1. КАРТА ФУНКЦИЙ

### 1.1 Создание драйверов (rw_init `FUN_080477c4`, порядок: tilt→battery→**BLADE→RIGHT→LEFT**)
Драйверы создаются через геттеры, каждый заполняет объект-«ops» (vtable) указателями функций:

| Мотор | ops-filler | init-функция (ops[0]) | set_dir (SPI) | run/coast (GPIO) | PWM-канал TIMER2 |
|---|---|---|---|---|---|
| НОЖ (blade) | `FUN_0806e0b4` / `FUN_0806dff8` | `FUN_0805a858`* | `FUN_08022a80`→`FUN_0801f4c6` | **нет** | CH1 (`FUN_0807f696(...,1,..)`) |
| ПРАВЫЙ (right)| `FUN_0806e79c` / `FUN_0806e6d0` | `FUN_0805b820`* | (SPI, аналог) | **`FUN_0806fc2c`** (PD4, бит 0x10) | CH2 |
| ЛЕВЫЙ (left) | `FUN_0806e4e4` / `FUN_0806e418` | **`FUN_0805aee0`** | `FUN_0805f300`→`FUN_0801f4c6` | **`FUN_0805f3d8`** (PD7, бит 0x80) | CH3 (`FUN_0807f474/696(...,3,..)`) |

`*` — не декомпилировано (пробел), адрес взят из ops[0] в filler'е.
Два filler'а на мотор = две версии платы (board type `0x50dc` и `0x708`, выбор в rw_init).

### 1.2 Общие A4963/SPI/GPIO примитивы
- **A4963 write+verify** `FUN_0808408c(handle, word)`: пишет `word`, читает reg обратно
  (`FUN_0806caac`, адрес reg = `word & 0xe000`), сверяет `word&0xfff == readback&0xffff`,
  до 0x31 повторов. → каждая запись конфигурации верифицируется.
- **A4963 transfer** `FUN_080840d8(handle, word)`: CS assert = `(*handle[0])()`, шлёт
  `word | 0x1000` (**бит WR=0x1000**) через `FUN_0807dd98`, CS deassert = `(*handle[1])()`.
- **A4963 direction** `FUN_0801f4c6(handle, cfg, dir)`: правит **бит 0x2 слова cfg+0xe** (= reg7),
  перезаписывает reg7 по SPI. Направление = бит1 reg7. Тормоз — соседний хелпер `FUN_0801f4b8`.
- **GPIO set/clear** `FUN_080534f8(port,mask)` пишет `port+0x14`; `FUN_080534fc(port,mask)`
  пишет `port+0x10` (пара set/reset-latch). **Это единственный «дискретный» выход драйвера.**
- **GPIO mode/AF** `FUN_08053558` (CTL), `FUN_08053608` (AF-mux). **RCU-enable** `FUN_0806c77c(id)`
  (id>>6 = смещение EN-регистра, id&0x1f = бит).
- **PWM (TIMER2 CHxCV/CHCTL)** каналы: `FUN_0807f474` (config CH), `FUN_0807f696` (duty),
  `FUN_0807f86c` (TIMER3-канал config), `FUN_0807f648/6b4/7cc/3f8` — enable/полярность/старт.
- **Тахо (TIMER3 input-capture)** `FUN_08062c64(ch,cb)` + `FUN_08062c8c(ch,ctx)` —
  регистрация callback захвата. **Вызывается ТОЛЬКО колёсными init'ами.**

## 2. A4963 CONFIG-СЛОВА

Формат слова A4963: **биты 15:13 = адрес регистра (0..7)**, бит 12 = WR (добавляется в
transfer'е `|0x1000`), биты 11:0 = данные. Ниже — 8 слов (reg0..reg7), которые ЛЕВЫЙ init
(`FUN_0805aee0`) кладёт в объект по смещениям +0x30..+0x3e и затем шлёт 7 записей
(reg0..reg6 + reg7; reg5 в цикле пропущен — пишутся индексы 0,1,2,3,4,5?,7, см. код §4).

| reg (15:13) | НОРМА (fast) | SLOW-режим | заметки по полям A4963 |
|---|---|---|---|
| reg0 `000` | `0x03E8` (=1000) | `0x01A8` (=424) | данные 0x3E8/0x1A8 — таймингы (off-time / t_blank) |
| reg1 `001` | `0x22DF` | `0x2ADF` | данные .df — dead-time / blank; в slow старший ниббл 0x2A |
| reg2 `010` | `0x4753` | `0x47D3` | VDS/current-limit порог; slow меняет один бит |
| reg3 `011` | `0x6721` | `0x6721` | одинаково — фикс. поле |
| reg4 `100` | `0x8735` | `0x8745` | bemf/commutation; slow иной |
| reg5 `101` | `0xA736` | `0xA736` | одинаково |
| reg6 `110` | `0xC000` | `0xC000` | одинаково — данные=0 (маска/режим) |
| reg7 `111` | **`0xEE0D`** | **`0xEE0D`** | **RUN-регистр: RUN удержан, direction=бит1, brake — правится рантаймом** |

Расшифровка reg7 `0xEE0D` = `1110 1110 0000 1101`b: адрес=111 (reg7), данные=0xE0D.
Направление меняет `FUN_0801f4c6` (бит 0x2). **reg7 держит RUN — чип, будучи запитанным,
обязан крутиться (см. вывод расследования о auto-run).**

> **Нож и правый:** их init'ы не декомпилированы, но (а) используют тот же `FUN_0808408c`
> путь записи, (б) их direction идёт через тот же `FUN_0801f4c6` (reg7 бит1), (в) по памяти
> проекта reg7=0xEE0D общий для всех трёх. Отдельная таблица config-слов ножа/правого требует
> дизассемблера ARM-thumb (на хосте недоступен); архитектурно они идентичны левому.

## 3. ТАЙМЛАЙН run / brake

### 3.1 ЛЕВЫЙ init `FUN_0805aee0` (авторитетно)
1. malloc объекта 0x48, обнуление полей.
2. Читает режим платформы `FUN_08050578()[0x54]` → выбирает **fast** (0/2) или **slow** (1/3) config-набор → пишет 8 слов в +0x30..+0x3e.
3. `FUN_0805f4ac()` — конфиг GPIO/PWM левого: RCU `0x600`, порт `0x605`/`0x604`; ставит пины бит 0x20 (**PD5 = левый CS**), бит 0x40 и AF (0x48) — TIMER2 CH3 PWM (PC9).
4. `FUN_0801f2f4(obj+0x28)` — инициализация SPI1-handle A4963.
5. `FUN_0806c77c(0x701)` — RCU-enable; затем **TIMER2 CH3**: `FUN_0807f474(TIMER2,3,cfg)`,
   `FUN_0807f696(TIMER2,3,0)` duty=0, `FUN_0807f648(TIMER2,3,0x60)`, `_6b4`, `_3f8`, `_7cc` — старт канала.
6. **TIMER3 (тахо)**: `FUN_0807f86c(TIMER3,1,cfg)`, `_9a0/_998`, и
   **`FUN_08062c64(4, cb)` + `FUN_08062c8c(4, ctx)`** — регистрация input-capture колеса.
7. **8× `FUN_0808408c(obj+0x28, reg_word)`** — залив config A4963 (reg0..reg6, reg7) с verify.
   Ошибка любой → лог `a4963` + возврат -1.

### 3.2 ЛЕВЫЙ run/brake
- **direction/старт** `FUN_0805f300(dir)`: `FUN_0801f4c6(obj+0x28, obj+0x30, dir)` — reg7 бит1 по SPI.
- **run/coast GPIO** `FUN_0805f3d8(on)`: если старт → `FUN_080534f8/fc(DAT_0805f430, **0x80**)`
  = **PD7** set/clear (по флагу полярности obj+9). Карта: **PD7 LOW = run**.
- **PWM duty**: `FUN_0807f696(TIMER2, 3, duty)` (CH3CV).

### 3.3 ПРАВЫЙ run/coast `FUN_0806fc2c(on)`
Точный аналог левого, но GPIO-бит **0x10 = PD4** (`FUN_080534f8/fc(DAT_0806fc84, 0x10)`),
PWM = CH2, тахо-канал тот же механизм. direction — через `FUN_0801f4c6` (reg7).

### 3.4 НОЖ run/brake (blade)
- **direction** `FUN_08022a80(dir)`: **только** `FUN_0801f4c6(obj+0x20, obj+0x28, dir)` — reg7 по SPI.
- **speed/brake** `FUN_08022dc8(speed)`: при speed<200 → `FUN_0801f4b8` (A4963 brake по SPI) +
  `FUN_0807f696(TIMER2, **1**, 0)`; иначе PWM duty на **CH1**.
- **GPIO run/coast линии НЕТ.** Управление ножом = чисто SPI-конфиг A4963 + PWM CH1.

## 4. КЛЮЧЕВОЙ КОД (аннотировано)

```c
// A4963: записать конфиг-слово с WR-битом и верификацией (общий для 3 моторов)
FUN_0808408c(handle, word) {
  do { transfer(handle, word);                 // шлёт word|0x1000 (WR)
       read_reg(handle, word & 0xe000, &rb);    // читает тот же reg (адрес=top3)
  } while (word&0xfff != rb&0xffff && ++n<0x31);// verify low-12 бит
}

// A4963 направление = reg7 бит1 (одинаково у ножа и колёс)
FUN_0801f4c6(handle, cfg, dir){
  w = *(u16*)(cfg+0xe);                          // cfg+0xe = reg7 (=0xEE0D)
  w = dir ? (w|2) : (w & ~2);
  *(u16*)(cfg+0xe)=w;  FUN_0808408c(handle, w);  // перезалив reg7 по SPI
}

// ★ КОЛЁСА: физический GPIO run/coast (у ножа ОТСУТСТВУЕТ)
FUN_0805f3d8(on){   // ЛЕВЫЙ
  if (start) (flag==-1) ? SET(PORT,0x80) : CLR(PORT,0x80);  // 0x80 = PD7
}
FUN_0806fc2c(on){   // ПРАВЫЙ
  ... SET/CLR(DAT_0806fc84, 0x10);                          // 0x10 = PD4
}

// НОЖ: направление/тормоз — только SPI A4963, никакого дискретного enable
FUN_08022a80(dir){ FUN_0801f4c6(obj+0x20, obj+0x28, dir); } // всё
```

## 5. ★ АСИММЕТРИЯ НОЖ vs КОЛЁСА

| Признак | НОЖ (blade) | КОЛЁСА (left/right) | Что это значит |
|---|---|---|---|
| A4963 config (reg0-7) | тот же путь `FUN_0808408c`, reg7 RUN-held | то же самое | **симметрично** — не причина |
| direction | SPI reg7 бит1 (`FUN_0801f4c6`) | SPI reg7 бит1 (тот же хелпер) | симметрично |
| **дискретный GPIO run/coast** | **НЕТ** | **ЕСТЬ: PD7 (лев), PD4 (прав)** | ★ единственный дискретный выход у колёс; но **уже протестировано LOW=run — не помогло** (WHEELS-STATE) |
| PWM TIMER2 | CH1 | CH2 (прав), CH3 (лев) | симметрично (разные каналы) |
| **TIMER3 тахо** (`FUN_08062c64/8c`) | нет | **есть** (input-capture колеса) | сенсор скорости, **не силовой путь** |
| ops-slot +0x24, +0x54 | нет (есть puVar4[7]) | **есть** (fptr `0807894x`/`0807afxx`) | эти адреса — в области `dpport/report`-сервиса → **репорт скорости/одометрия, не питание** |
| силовой рейл | живой (нож крутится нашей fw) | коммутируемый **20U**, выкл. под нашей fw | ★ причина «колёса мертвы» |

### Кандидаты на «питание/enable колёс» — вывод
1. **Прошивочной асимметрии питания НЕТ.** Все дискретные/периферийные различия нож-vs-колёса
   исчерпываются: (a) run/coast GPIO **PD7/PD4** — уже проверено, не включает рейл;
   (b) TIMER3-тахо и (c) ops-репорт-callbacks `0807894x/0807afxx` — это **сенсорика/телеметрия**,
   не силовой путь. Ни одного per-wheel power/gate-GPIO в firmware не существует.
2. Это **подтверждает** гипотезу из `WHEELS-STATE-2026-07-08.md`: **enable рейла 20U — НЕ firmware-GPIO**.
   Нож сидит на постоянно-живом рейле (потому крутится auto-run от reg7=RUN), колёса — на
   коммутируемом 20U, чей включатель вне GD32.
3. **Остаются нефирмварные / непрошитые кандидаты** (в порядке приоритета):
   - **BMS discharge-enable по USART2** — включение силового разряд-FET пака (нож питается
     иначе/раньше). ★ следующий шаг — реверс команды «enable discharge».
   - **`movebase_snk_v10.c`** (сервис движения колёс, не разобран) — может дёргать что-то при
     старте езды поверх драйвера.
   - **Аппаратный high-side gate ключа 20U** (Q10/Q17/Q14) — прозвон затвора (низкий приоритет).

### Что НЕ удалось извлечь (ограничение)
Config-слова reg0-7 **ножа** (`0805a858`) и **правого** (`0805b820`) — их init'ы в пробелах
Ghidra, а ARM-thumb дизассемблер на хосте недоступен. Восстановлены косвенно (общий путь
записи + reg7=0xEE0D). Для байт-точной таблицы ножа/правого нужен объектный дизасм в контейнере.
