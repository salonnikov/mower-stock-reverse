# Заводская прошивка MI 302 — карта модулей + таймлайны (chip1 + chip2)

Досконально: что делает заводская прошивка — по модулям и по веткам событий, с точностью до
функции / пина / шины. Главный вопрос: **чем заводская включает силовой рейл 20U колёс** (нож на
живом рейле крутится и нашей fw, колёса мертвы). Разбор оффлайн (декомпиляция + дамп), без гадания.

Чип: **GD32F30x_CL** (F1-периферия). GPIOA=0x40010800, RCU=0x40021000 (APB1EN=+0x1C/APB2EN=+0x18/AHBEN=+0x14),
GPIO F1-стиль (BOP=+0x10 set, BC=+0x14 clear, OCTL=+0x0c). Таймеры: TIMER2=0x40000400 (мотор-PWM),
TIMER3=0x40000800 (тахо). SPI1=0x40003800 (A4963). USART2=0x40004800 (BMS). Наш `gd32_regs.h` — эти же базы `[VERIFIED]`.

## ЕДИНЫЙ ТАЙМЛАЙН (по веткам)

### A. Включение питания (01)
`reset` → бутлоадер `boot_sys_init FUN_08000f38`: клоки GPIOA-E+AFIO → **PE12=HIGH (главная защёлка)** →
**PE7=HIGH (aux)** → comms-пины (USART0/UART3/SPI0, UART-DE LOW), PE0/1/5=OUT-OD LOW → `FUN_08001b4c`
при power-on-reset → **PB0=HIGH (вторичная защёлка)** → teardown `FUN_08000e48` (гасит IRQ/TIMER0/DMA/SPI0,
защёлки не трогает) → **app** `main FUN_08061714` → `FUN_0807f010` (держит клоки портов защёлок + flash self-check)
→ FreeRTOS `FUN_0806bbd8` (task «initial» @0x0805bc28) → `rw_init FUN_080477c4` создаёт драйверы
**tilt→battery→BLADE→RIGHT→LEFT** (vtable) → FSM **state 3 (idle)**, `fsm_set FUN_0807976c` пишет @0x200000bc.

### B. Пинкод / разблокировка (02)
Кнопка `FUN_0800d034` (вход бит10, антидребезг) → `FUN_0800cf50` лог `key_press_power_on`, флаг |0x40.
Дисплей (ESP32) шлёт по UART cJSON-кадр `0x26 | payload | CRC8(poly 0x8C) | 0x23` (опц. XOR 0x5b):
`dp_receive FUN_0804721c`→де-XOR `FUN_0803953c`→валидация `FUN_0806e938`→cJSON `FUN_080470f0`
(диспатч по таблице 16, ключ `cmd&0xFF000000`). Класс `0x30…`→userset `FUN_08044c80` (switch):
**case 09 = сверка пина** (json vs `DAT_08060d38`; ок→`result=true`+сброс счётчика; нет→инкремент NVM
«run_param»+0xb8, >9→lock+событие 0x20; ответ `FUN_08072e08`). Разблокировка = request/response;
**state 3 ставит процесс-слой** `FUN_08069848`/`FUN_08049d14(3)`. Силовых записей нет.

### C. «Косить» (03) — state 3→4→5
`idle FUN_080270a8` (process_wait): safety `FUN_0804f758` + гейт расписания `FUN_0805deec` → `fsm(4)`
(при переходе — только запись state, НИ GPIO/TIMER/SPI). **departure** → `FUN_08077e10(1)` (movebase):
скорость `FUN_0804f2c8(0x3c,0x87)` → vtable колёсам `(600, dir, speed)` → vtable «enable» @+0xa8. Железо за
vtable: **TIMER2 CH2CV(прав)/CH3CV(лев)=ШИМ**, **направление=SPI-write A4963** (`FUN_0801f4c6→FUN_0808408c`,
`word|0x1000`), **run/coast=PD7(лев)/PD4(прав)**. Пройдено departure-расстояние → `fsm(5)` cutting → нож
`FUN_0802bce4`. **Отдельного «включить рейл 20U» шага НЕТ.**

### D. «Домой» / док (03) — тот же movebase-путь; charge-init (0x08085xxx) за пределами декомпила.

### E. Моторы (04)
3× A4963 на общей SPI1, vtable-объекты. Конфиг: `FUN_0808408c` write+readback (reg-addr=биты15:13, WR=0x1000
в трансфере `FUN_080840d8`). Направление у всех — `FUN_0801f4c6` (бит 0x2 reg7). A4963 левого reg0-7 норма
`03E8,22DF,4753,6721,8735,A736,C000,EE0D`; slow `01A8,2ADF,47D3,6721,8745,A736,C000,EE0D`. reg7=`EE0D`=RUN.
Wheel-only: PD7/PD4 run/coast + TIMER3-тахо. Ножу дискретный enable не нужен.

### F. BMS / пак (05)
USART2 19200 8N1 half-duplex PD8/PD9. Кадр `1C A1 <LEN> <op> <args> <CRC8/MAXIM>`, ответ `3A A3`:
`C1`=connect/телеметрия (×4), `C3`=опрос пака, `0x53`=опрос ячеек, `CE`(55×7)=link-wake/resync,
`B0..B4`=режим заряда/state (into/exit charge, диспетчер `FUN_08072948`, шлёт только при enable==1 @+0xa5).
Заводской цикл: init→CE→connect→initial-poll→keep-alive C3+53→charge по доку. **Команды enable-разряда мотор-FET НЕТ.**

### G. chip2 (06)
GD32F4xx сенсорной платы ГРАНИЦЫ: АЦП+DMA периметра (`bdsensor_init`), детект волны, датчики подъёма.
Линк с chip1 = UART/cJSON (chip1 мастер, тег bdport). К питанию моторов прямо не причастен.

## ★★ ВЫВОД: чем включается рейл 20U колёс — ранжированный план

На всём заводском софт-пути (boot / pin / mow / home / motors / bms) **отдельного действия «включить
силовой рейл колёс» НЕТ** сверх того, что мы уже воспроизводим (PWM + направление-SPI + run PD7/PD4 +
защёлки PE12/PE7/PB0). Разбор дал **два конкретных firmware-теста** до любого железа:

### 1. ★★ Починить SPI1 → добиться, что конфиг A4963 реально залетает на КОЛЁСНЫЕ чипы
Наш `verify=0xFFFF` даже на живом ноже ⇒ **SPI1-чтение не работает, вероятно и запись не применяется.**
Гипотеза: нож крутится на POR-дефолте A4963, а колёсным чипам дефолт = coast/standby, им ОБЯЗАТЕЛЬНА
залетевшая SPI-конфига (reg0..7 вкл. `EE0D` + направление `FUN_0801f4c6`). Тест: починить SPI1 read/write,
проверить `verify != 0xFFFF` на колёсных A4963, убедиться что reg0-7 записались → крутить колёса.
(Частично пересматривает прежнее «A4963 auto-run, SPI не нужен» — верно для ножа, НЕ доказано для колёс.)

### 2. ★ BMS keep-alive (watchdog связи пака)
Мы слали паку только `C1`; завод постоянно шлёт `CE`-wake + keep-alive `C3`+`0x53`. Если пак роняет
силовой FET по watchdog связи — нужна устойчивая периодика этих кадров (не спец-команда). Тест: реализовать
`CE→connect→периодику C3+53`, замерить VBB колёс. Не поднимется — гипотеза «пак гейтит колёса» закрыта.

### 3. Аппаратный high-side ключ рейла 20U (Q10/Q17/Q14)
Дефолтный исход, если (1) и (2) мимо. Прозвон затвора завод-на-ходу vs наш. По решению пользователя — низкий приоритет.
