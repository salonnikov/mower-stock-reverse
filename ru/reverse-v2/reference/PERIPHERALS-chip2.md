# CHIP2 (GD32F30x, плата коилов границы) — карта периферии и IO

> Чип: **chip2** = плата коилов/сенсоров границы (border/coil sensor board). GD32F30x.
> Дамп: `dist/gd32-mainboard-chip2-dump-v1.bin`, база `0x08000000`.
> Декомпил: `reverse-v2/chip2/decompiled_all.c`, `symbols.txt`, `memory_map.txt`, `functions_index.csv`.
> Метки доверия: **[V]**=verified (offset/строка кода/литерал в дампе), **[I]**=inferred, **[U]**=unknown.
>
> ⚠️ ВСЁ ниже относится к **chip2**. Не путать с chip1 (главный GD32F305). У chip2 СВОЙ USART2.

## 1. ADC-тракт коилов — dual/sync ADC0 + ADC1

Инициализация: **`FUN_08019bf4` @ 0x08019bf4** (dual-ADC init) и **`FUN_08019d34` @ 0x08019d34** (DMA), вызываются из **`FUN_08012b6c` @ 0x08012b6c = `bdsensor_init`** (файл `..\src\platform\driver\driver_board_sensor\driver_bdsensor.c`, строка `driver_bdsensor.c` @0x08012ca0).

Литералы base подтверждены чтением дампа:
- `DAT_08019cf0 = 0x40012400` = **ADC0** [V]
- `DAT_08019cf4 = 0x40012800` = **ADC1** [V]
- `DAT_08019da0 = 0x40020000` = **DMA0** [V]
- `DAT_08019da4 = 0x4001244c` = **ADC0_RDATA** (ADC0+0x4C, regular data register) [V]

### Каналы (декодировано из `FUN_08012a04` = adc_regular_channel_config(base, rank, channel, sample_time)):
- `FUN_08012a04(ADC0, 0, 5, 7)` → **ADC0, rank0, channel 5, sample-time index 7** [V] (decompiled_all.c:14341)
- `FUN_08012a04(ADC1, 0, 9, 7)` → **ADC1, rank0, channel 9, sample-time index 7** [V] (decompiled_all.c:14342)

Механика `FUN_08012a04` (dc:6165): пишет 5-битное поле канала в RSQ2/RSQ1/RSQ0 (off 0x34/0x30/0x2c) и 3-битное поле sample-time в SAMPT1/SAMPT0 (off 0x10/0xc). Проверено — семантика GD32 стандартная. **Sample-time index 7 = 239.5 циклов ADC** (максимальный) [V] — т.е. максимально «медленная»/усреднённая выборка (коил = высокоимпедансный источник).

### Аналоговые пины (из `bdsensor_init`, GPIO в analog-mode, `FUN_08016ef0(port,0,4,mask)`):
- `FUN_08016ef0(GPIOA, 0,4, 0x20)` → **PA5 = ADC0_CH5** [V] (маска 0x20 = бит5)
- `FUN_08016ef0(GPIOB, 0,4, 0x02)` → **PB1 = ADC1_CH9** [V] (маска 0x02 = бит1; GD32: ch9=PB1)
- `FUN_08016ef0(GPIOA, 0,4, 0x80)` → **PA7** тоже в analog-mode [I] (маска 0x80 = бит7 = ADC_CH7; в regular-последовательности НЕ сконфигурирован — резерв/инъекция/мониторинг, назначение [U])

### Sync/dual режим и DMA:
- `FUN_080129ec(0x20000)` в init — установка sync-режима ADC (dual regular parallel). В dual-sync GD32 результат ADC0 (младшие 16б) + ADC1 (старшие 16б) кладётся одним словом в **ADC0_RDATA (0x4001244c)** [V/I].
- `*(ADC0+8) |= 0x100` (dc:14353) — включение DMA-бита в ADC0_CTL1 [V].
- **`FUN_08019d34`**: `dma_deinit(DMA0, ch0)` → `dma_init(DMA0, ch0, cfg)` где cfg.periph_addr = `0x4001244c` (ADC0_RDATA), circular, mem-increment, 16-бит, high-priority; `dma_channel_enable(DMA0,0)` + NVIC (`FUN_08017bc4(0xB,5,0)` → IRQ 0x0B = **DMA0_Channel0_IRQn**) [V]. **DMA0 Channel 0** читает ADC0_RDATA по кругу [V].

### Буфер выборок и baseline:
- Буфер волны выделяется динамически в **`FUN_08019e34` @ 0x08019e34**: поле длины (`+0x92`) = **800** отсчётов, malloc-ит 3 буфера: `+0x48` (800×2 B), `+0x68` (800×2 B), `+0x70` (800×4 B) [V]. Соответствует строкам «left wave data», «disturb wave», «enqueue wave to disturb wave».
- Текущий одиночный отсчёт коила: `FUN_08016a90` возвращает `*(0x2000004c)` (16-бит) [V].

### 🔧 Baseline / нормировка (ВАЖНО для перекалибровки под новые коилы):
В `bdsensor_init` (dc:6349-6362) при старте выполняется **автозамер базовой линии**: 5 раз читается ADC коила, берётся среднее `sum/5`, пишется в `*_DAT_08012c88 = 0x20000094` (16-бит **base voltage**) [V].
- Если замер сбоит → default **2048** (0x800, midscale 12-бит) — строка «base voltage =%d error, set default 2048» @0x080174ef [V].
- Сигнал коила далее интерпретируется относительно этой базовой линии (вычитание DC-смещения).
- **Явного цифрового множителя усиления в тракте НЕТ.** «Усиление» задаётся: (а) параметрами возбуждения TIMER1 (см. §4), (б) внешним аналоговым фронтендом (вне МК). Цифровая нормировка = только вычитание `base_voltage` (0x20000094).

### Лево/право (какой канал какая сторона):
- **[U]** — код НЕ маркирует ADC0-ch5 / ADC1-ch9 как «левый»/«правый» напрямую. Известно только: PA5=ADC0_CH5 и PB1=ADC1_CH9 — две стороны коила. Разделение left/right происходит программно из dual-слова (младшая половина = ADC0, старшая = ADC1), но соответствие половины конкретной стороне **не доказано** ([I]: ADC0/младшая = одна сторона, ADC1/старшая = другая).

## 2. USART2 (0x40004800) — линк к chip1

Init: **`FUN_080004d4` @ 0x080004d4**, вызывается из `FUN_080005e0`.

- **Baud 115200** [V]: `FUN_08001d2c(&USART2_STAT0, 0x1c200)` — 0x1c200 = 115200 (dc:497).
- Кадр 8 бит, конфиг через `FUN_08001e4c(&USART2,0x304)` и семейство сеттеров (dc:498-504) — 8 бит данных, стандартный (8N1 [I]).
- **NVIC**: `FUN_08001a68(0x27,3,0)` → IRQ **0x27 = 39 = USART2_IRQn** (GD32F30x), приоритет 3 [V].
- **Пины (GPIOB, без ремапа — GPIOC/D отсутствуют в дампе)**:
  - `FUN_080014d8(&GPIOB_CTL0, 0x18, 4, 0x400)` → **PB10 = USART2_TX** (маска 0x400 = бит10, AF push-pull) [V]
  - `FUN_080014d8(&GPIOB_CTL0, 4, 4, 0x800)` → **PB11 = USART2_RX** (маска 0x800 = бит11) [V]
  - (Дефолтная раскладка USART2 GD32 = PB10/PB11, ремап не применён [V])
- **DMA (DMA0)**:
  - **TX = DMA0 Channel 1** [V/I]: в отправке `FUN_08019a18` (send_string) → `dma...(_DAT_08019b3c, 1, len)` (dc:14295-14296). Соответствует GD32 USART2_TX→DMA0_CH1.
  - **RX = DMA0 Channel 2** [V/I]: `FUN_080008d0(&DMA0_INTF, 2, &DAT_20000078)` + count `0x100`=256 (dc:474-475, 603-604). RX-буфер **0x20000078**, размер 256 B. Соответствует GD32 USART2_RX→DMA0_CH2.

### Кадр протокола (chip2↔chip1) — что подтверждено:
- **Заголовок = 0xA5** [V]: `if (DAT_20000078 == -0x5b ...)` (dc:467), -0x5b как байт = 0xA5. Первый байт RX-буфера.
- **Байт команды** = RX[1], диапазон 1..0x15, диспетчеризация по jump-таблице (dc:467-470) [V].
- **Полезная нагрузка XOR 0x5B** [V]: `*(param_1+uVar2) ^= 0x5b` (dc:7630, 7674) — скремблирование/дескремблирование тела кадра ключом 0x5B.
- **Концевой маркер '#' = 0x23** [V]: `FUN_0801b6d8(&local_c, 0x23)` (dc:7400).
- Контрольная сумма кадра: **[I]** есть (задача упоминает CRC8) — точный алгоритм программный, в декомпиле явного полинома CRC8 не выделено; аппаратный блок **CRC (0x40023000)** используется НЕ для кадра, а для **CRC32 self-test флеша** (IEC60730, dc:638-666, `CRC_DATA`/`CRC_CTL`). Не путать.
- Драйвер порта: `..\src\platform\driver\driver_port\driver_mboard_port_snk_v2.c` (строка @0x08019adc), тег лога «mport drv».

## 3. GPIO — концевики lift + прочее

### Lift-концевики (2 шт):
Обработчик: **`FUN_08013970` @ 0x08013970** (`deal_lift_sensor`, файл `process_comm.c`) [V].
- Читает **2 цифровых входа** через указатели-методы драйвера lift: `read_ch1()` (struct+8→+4) и `read_ch2()` (struct+8→+8) (dc:7509-7510) [V].
- Логика состояний: **both lifted / left lifted / right lifted / lift none** (строки @0x08013abc/0x08013a7f/0x08013ac8/0x08013ad8) [V].
- **Дебаунс**: счётчик с порогом **10** тиков подряд перед сменой состояния (dc:7515-7566) [V].
- **Пины концевиков: [U]** — читаются через абстракцию lift-драйвера (указатели функций), конкретные GPIO задаются в его init (не локализован точно). Порт — GPIOA или GPIOB (других портов в дампе нет) [I].
- Строки init: «init lift driver failed» @0x080172a8.

### Прочие GPIO (подтверждённые):
| Пин | Назначение | Метка |
|---|---|---|
| PA5 | ADC0_CH5 (коил, analog) | [V] |
| PA7 | analog (ADC_CH7, назначение неясно) | [I]/[U] |
| PB1 | ADC1_CH9 (коил, analog) | [V] |
| PB10 | USART2_TX (линк к chip1) | [V] |
| PB11 | USART2_RX (линк к chip1) | [V] |

Хелперы GPIO: `FUN_080014d8` (config CTL0/CTL1 нибблами), `FUN_08016ef0` (analog/режим по маске).

## 4. TIMER — возбуждение коила (TIMER1 CH1 PWM)

Из `bdsensor_init` (dc:6335-6345), base = **`0x40000000` = TIMER1** [V]:
- `FUN_0801af7c(0x40000000, &cfg)` = timer_init; cfg: **prescaler = 0x0B (11)**, **period/CAR = 199**, остальное 0 (dc:6335-6339) [V].
- `FUN_0801ac58(0x40000000, 1, {mode=1})` = timer_channel_output config, **канал 1 (CH1)** [V].
- `FUN_0801ae7a(0x40000000, 1, 100)` = **pulse/CH1CV = 100** (≈50% от 199) [V].
- `FUN_0801ae2c(0x40000000, 1, 0x70)` = output mode = **PWM** (0x70 = TIMER_OC PWM) [V].
- `FUN_0801ae98(0x40000000, 1, 0)` = доп. конфиг (dc:6345).

**Итог: возбуждение коила = TIMER1 CH1, PWM ~50% (pulse 100 / period 199), prescaler 12 (0x0B+1).**
- Частота [I]: при таймер-клоке 120 МГц → 120e6/12/200 ≈ **50 кГц** возбуждения коила (правдоподобно для индуктивного датчика границы). Точный клок APB1×2 не перепроверен → [I].

### 🔧 Для перекалибровки под новые коилы крутить здесь:
- **prescaler (0x0B) и period (199)** → частота возбуждения коила (dc:6335-6336).
- **pulse (100)** → скважность/энергия возбуждения (dc:6343).
Плюс baseline из §1 (0x20000094) — цифровое смещение.

### TIMER0 / TIMER2:
- **[I]** используются (литералы base в дампе: TIMER0 ×2, TIMER2 ×1), назначение не локализовано — вероятно таймбейс/тик планировщика или синхронизация выборки. Привязка к коилу **[U]**.

## 5. DMA и прочая периферия

### DMA0 (0x40020000) — единственный задействованный DMA-контроллер [V]:
| Канал | Назначение | Evidence |
|---|---|---|
| CH0 | ADC0_RDATA → буфер волны коила (circular) | [V] FUN_08019d34 |
| CH1 | USART2 TX | [V/I] FUN_08019a18 |
| CH2 | USART2 RX (буфер 0x20000078, 256 B) | [V] FUN_080004d4/FUN_08000694 |

DMA1 (0x40020400): в коде есть только проверки `param==&DMA1_INTF` в общих хелперах (dc:711…827) — **сам DMA1 активно не конфигурируется** [I].

### CRC (0x40023000):
- Аппаратный CRC32 — **только IEC60730 self-test флеша** (dc:638-666), «FLASH CRC32 Test» строки @0x0801a768. НЕ для кадра USART2 [V].

### Прочее:
- **FMC** (0x40022000, 357 обращений) — работа с флешем/self-test [V].
- **PMU / RCU / NVIC** — системные (тактирование, питание, прерывания).
- **IEC60730 safety self-test** активен: CPU/FLASH-CRC/Clock/PC/RAM/ADC тесты (строки @0x0801a52c…, `adc test(PreRun)` @0x0801a910 использует **ADC2**) [V].
- Логирование: EasyLogger V2.2.99 (`elog.c`), теги «hr_bd», «mport drv», «init_bd».
- ОС: FreeRTOS (`tasks.c`/`queue.c`/`heap_4.c`/`port.c`).

### Тактирование (RCU clock-enable, `FUN_08019148`/`FUN_08001bf8` с enum):
В `bdsensor_init` включаются клоки enum-ами 0x602,0x603,0x609,0x60a,0x500,0x700; в system-init — 0x300,0x400,0x500,0x600,0x602-0x606,0x700,0x712. Точное декодирование enum→периферия не выполнено, но согласуется с литерал-доказательством: клокаются GPIOA/GPIOB, DMA0, ADC0/ADC1, TIMER1 [I].

## Главные [U]-дыры
1. **Лево/право коила** — какой из ADC0_CH5(PA5)/ADC1_CH9(PB1) какая сторона: не доказано.
2. **Пины lift-концевиков** — точные GPIO (порт A/B) скрыты за абстракцией lift-драйвера.
3. **Назначение PA7** (analog, ADC_CH7) — сконфигурирован, но не в regular-последовательности.
4. **TIMER0/TIMER2** — задействованы, но роль не локализована.
5. **CRC8 кадра** — присутствие вероятно, точный алгоритм/полином не выделен (аппаратный CRC занят self-test'ом флеша).
