# A4963 драйвер: пины CS / enable / SPI1 / привязка PWM

Побайтовая разборка из `dist/factory-full.asm` (база 0x08000000) и дампа
`dist/gd32-mainboard-dump-v1.bin`. Метки: **[V]** доказано байтом/строкой asm,
**[I]** правдоподобно, **[U]** не докопал.

Периферийные базы (из проектных якорей, подтверждены использованием):
GPIOD=0x40011400 (BOP +0x10 = set/HIGH, BC +0x14 = reset/LOW, OCTL +0x0C).
GPIOB=0x40010C00. GPIOE=0x40011800. SPI1=0x40003800. TIMER2=0x40000400.

---

## Ключевой факт архитектуры: CS сидит в callback'ах объекта, не в теле SPI

SPI-кадр A4963 шлёт `FUN_080840d8` (send, offset 227102). Она НЕ трогает GPIO
напрямую — CS дёргается через два указателя-функции в объекте `r7` (arg0):

| asm offset | инструкция | смысл |
|---|---|---|
| 0x80840fa | `ldr r0,[r7,#0]; blx r0` | **CS assert** (перед кадром) |
| 0x8084136 | `ldr r0,[r7,#4]; blx r0` | **CS deassert** (после кадра) |

Литеральный пул send (offset 227158-227162):
`0x8084160`→**0x000186a0** (тайм-аут 100000), `0x8084164`→**0x20000580** (обёртка SPI),
`0x8084168`→**0x40003800** (SPI1). **[V]** SPI1 = 0x40003800 подтверждён байтом пула.

Кадр: verify-write `FUN_0808408c` (offset 227079-227080): `r7 = frame & 0xFFF`
(12 бит данных), `r8 = frame & 0xE000` (3 старших = адрес регистра A4963).
send OR'ит `r1 | 0x1000` (offset 227106) — бит12 = команда записи A4963.
Итог: у каждого «мотора» СВОЙ объект-драйвер со СВОИМИ CS-callback'ами; выбор
мотора = какой объект вызываешь, а не бит в кадре. **[V]**

## 1. CS каждого мотора  ✅ РАЗРЕШЕНО

Каждый create вписывает пару CS-thunk'ов в объект по смещениям +0x28/+0x2c
(они же +0/+4 внутри SPI-объекта). Thunk'и — крошечные функции:
`movs r1,#маска; ldr r0,=GPIOx; b.w gpio_helper`.
gpio-хелперы: `0x80534f8` = `str r1,[r0,#20]` = **BC (+0x14) = LOW/выбор**;
`0x80534fc` = `str r1,[r0,#16]` = **BOP (+0x10) = HIGH/снятие** (offset 142283/142285).

### ЛЕВЫЙ мотор — CS = **PD5** [V]
- create `FUN_0805aee0` (offset 155576), объект `[0x2000054c]`.
- Установка callback'ов (offset 155660-155662): `[obj+0x28]=0x0805fdc9` (assert),
  `[obj+0x2c]=0x0805fdbd` (deassert). Пул offset 155806/155807.
- Assert `FUN_0805fdc8` (offset 163846): `movs r1,#0x20` (бит5); `ldr r0`=пул@0x805fdd0=**0x40011400** (GPIOD); `b.w 0x80534f8` → **PD5 LOW**.
- Deassert `FUN_0805fdbc` (offset 163841): `movs r1,#0x20`; `ldr r0`=пул@0x805fdc4=**0x40011400**; `b.w 0x80534fc` → **PD5 HIGH**.
- **[V] Левый CS = GPIOD бит5 = PD5**, active-low.

### ПРАВЫЙ мотор — CS = **PD4** [V]
- create в районе 0x805b6xx-0x805b9xx, объект `[0x2000057c]` (из set_right).
- Установка (offset 156825/156823): `[obj+0x28]=0x080705a5` (assert),
  `[obj+0x2c]=0x08070599` (deassert). Пул@0x805ba70/0x805ba6c.
- Assert thunk `LAB_080705a4` (offset 192341): `movs r1,#0x10` (бит4); `ldr r0`=пул@0x80705ac=**0x40011400** (GPIOD); `b.w 0x80534f8` → **PD4 LOW**.
- Deassert thunk `LAB_08070598` (offset 192330): `movs r1,#0x10`; `ldr r0`=**0x40011400**; `b.w 0x80534fc` → **PD4 HIGH**.
- **[V] Правый CS = GPIOD бит4 = PD4**, active-low.

### НОЖ (blade) — CS = **PD3** [V]  ⚠️ ИСПРАВЛЕНО (первичный вывод этого агента был неверен)
- ❌ Первичный вывод «нож = простой PWM, не A4963» — ОШИБКА: агент взял НЕ ту
  функцию (`FUN_0805a720`, malloc 32Б — это другой объект). Настоящий blade-драйвер =
  **`FUN_0805a858`** (`driver_blade_motor_snk_v2.c`, malloc **64Б**, объект `[0x20000540]`).
- **Проверено байтово (перекрёстно, файл B + прямой дизасм):**
  - `movw #0xee0d` (reg7 A4963) встречается **ровно 3 раза**: 0x805a8be (нож),
    0x805af34 (левый), 0x805b874 (правый) → **три A4963-драйвера**, нож в их числе.
  - CS-thunk ножа: assert `0x08022fd8` (`movs r1,#8; ldr r0=0x40011400; b.w 0x80534f8`=BC/LOW),
    deassert `0x08022fcc` (`movs r1,#8; …0x40011400; b.w 0x80534fc`=BOP/HIGH).
    Маска `#8`=бит3, порт `0x40011400`=GPIOD ⇒ **PD3, active-low**.
- **[V] Нож = 3-й A4963, CS = PD3.** (Отдельный PWM CH1 у него ТОЖЕ есть — скорость,
  как у колёс: SPI-конфиг/направление + PWM-duty.)

### Разрешение гипотез
- **PD5 = левый CS, PD4 = правый CS, PD3 = нож CS — ВСЕ ПОДТВЕРЖДЕНЫ [V]** (GPIOD, active-low).
- Наша прошивка (CS PD5/PD4/PD3) по CS-пинам **совпадает с заводом**.
- **PD5 vs USART1-remap**: прошивка гоняет PD5 как обычный GPIO-выход (прямые
  BC/BOP по 0x40011400 бит5). Значит на PD5 висит именно CS, USART1 сюда НЕ
  ремапнут в этой прошивке. **[V]**

## 2. Enable-пин(ы)  ✅ PB12 ПОДТВЕРЖДЁН

Общий enable = **PB12** (GPIOB, маска 0x1000), поднимается в HIGH (BOP/set).
- SET-thunk `FUN_08062bb4` (offset ~168679): `mov.w r1,#0x1000`; `ldr r0`=пул@0x8062bc0=**0x40010C00** (GPIOB); `b.w 0x80534fc` (BOP=HIGH). Есть и парный reset-thunk `LAB_08062ba4` (BC=LOW).
- Вызывается из инициализаций моторов (BOP HIGH): offset 154852 (0x805a7ee, blade-create), 155562 (0x805aebe, перед left-create), 156541 (0x805b7b6, right-create).
- **[V] PB12 = GPIOB маска 0x1000 — общий enable, драйвится HIGH при bring-up.**

Другие GPIO-thunk-пары, замеченные рядом (НЕ CS, назначение по месту):
`PB9` (GPIOB 0x200, offset 161918), `PE12` (GPIOE 0x1000, пул@0x806460c, offset 171565).
**[I]** вспом. линии (питание/подготовка), не A4963-CS.

## 3. SPI1 конфиг (CTL0/CTL1)

- **[V]** База SPI1 = **0x40003800** (пул send offset 227162).
- **[V]** Регистр данных = base+0x0C: `FUN_0807dd98` (offset ~216xxx):
  `str r1,[r0,#12]` — запись байта/полуслова в **SPI1_DATA (0x4000380C)**.
- **[V]** Транзакция A4963 = 16-битный кадр «write» (`frame|0x1000`), с обратным
  чтением и сравнением 12 бит данных (verify-write FUN_0808408c).
- **[U]** Точные значения **CTL0/CTL1** (режим CPOL/CPHA, делитель, битность 8/16)
  байтово НЕ локализованы: конфиг идёт через HAL-хендл (SPI-объект 0x20000580,
  [+4]=хендл), а не прямой записью литерала 0x40003800 в CTL — литерал в пулах
  только у send. Инит-структуру не дотрассировал. НЕ выдумываю.

## 4. PWM канал ↔ колесо  ✅ ПОДТВЕРЖДЕНО

Хелпер `FUN_0807f696(base, ch, val)` (offset 219254) — сеттер CHxCV TIMER:
ch0→`str [r0,#0x34]`=CH0CV, ch1→`+0x38`=CH1CV, ch2→`+0x3c`=CH2CV, ch3→`+0x40`=CH3CV.

| мотор | функция | вызов | канал | регистр | база (пул) |
|---|---|---|---|---|---|
| **левое колесо** | set_left `FUN_0805f620` | offset 163415 (0x805f9d8): `r1=#3` | **CH3** | **TIMER2 CH3CV 0x40000440** | пул@0x805fac4=0x40000400 [V] |
| **правое колесо** | set_right `FUN_0806fe66` | offset 191938 (0x80701f6) и 192089 (0x8070368): `r1=#2` | **CH2** | **TIMER2 CH2CV 0x4000043c** | пул@0x80702d8=0x40000400 [V] |
| **нож** | blade-create `FUN_0805a720` | offset 154817 (0x805a78c): `r1=#1` | **CH1** | **TIMER2 CH1CV 0x40000438** | пул@0x805a814=0x40000400 [V] |

- **[V] left=CH3 (0x40000440), right=CH2 (0x4000043c), blade=CH1 (0x40000438)** — всё на TIMER2 (0x40000400).
- Объекты: left `[0x2000054c]`, right `[0x2000057c]`, blade `[0x20000588]`. **[V]**
- Формула duty: **[I]** период ≈ **7200** (0x1c20). В set_left: `r6 = speed*7200`
  (offset 163069, `mul r6,r1,#0x1c20`), далее `udiv` на кусочные делители
  (0x5fd=1533, 0x17fd=6141 и т.д. — рампа/дедбанд), результат `uxth`→ пишется в
  CHxCV как r2. Точный кусочно-линейный закон не расписывал байтом.

## Короткий вывод (гипотезы → факт)
- **PD5/PD4 CS — ПОДТВЕРЖДЕНЫ [V]**: PD5=левый A4963 CS, PD4=правый A4963 CS
  (GPIOD, active-low, assert=BC/LOW перед кадром, deassert=BOP/HIGH после).
- **PD3 CS = нож (3-й A4963) — ПОДТВЕРЖДЁН [V]** (исправлено; см. раздел «НОЖ» выше).
- **PB12 = аппаратный NSS SPI1** (GPIOB 0x1000), софт-idle HIGH — это НЕ отдельный
  «A4963-enable». Отдельного GPIO-разрешения A4963 НЕТ: разрешение = питание VBB +
  reg7 RUN. (Уточнено файлом B; наша прошивка PB12→HIGH делает — совпадает.)
- **PWM — ПОДТВЕРЖДЁН [V]**: left=CH3, right=CH2, blade=CH1, все TIMER2.
- **SPI1**: база 0x40003800 и DATA@+0x0C [V]; точные CTL0/CTL1 (режим/делитель/
  битность) — **[U]** (HAL-хендл, не дотрассировал).
